# Завершение плавного обновления таблиц — 29.10.2026

Локальная реализация и предусмотренные проверки завершены, включая установленный Safari 26.6.2. Коммит, push и прод не затрагивались. Авторизация остаётся отдельной отложенной задачей. Работа без дополнительных агентов.

Прежний сбой Safari воспроизведён и объяснён ошибкой измерителя: скрипт выбирал ячейку до завершения отрисовки после прокрутки. В диагностическом повторе он редактировал F9800001, который затем оказывался вне видимой области, и искал новое значение среди видимых строк. БД подтвердила правильное сохранение именно этого стыка; его прежний DOM-узел уже был выгружен. Исправленный помощник ждёт отрисовку, проверяет попадание указателя и выполняет настоящий двойной щелчок. Все девять последующих сохранений прошли со сверкой ID и значения в БД; исправлений приложения для этого случая не потребовалось.

## Что изменилось

- Общая таблица журнала, ЛНК и ПСТО получает согласованный снимок загруженных блоков. При прежнем составе и порядке AG Grid заменяет только изменившиеся данные, сохраняя узлы строк, раскрытые группы и прокрутку. Сверяются также связанные стыки, статусы и итоги.
- Создание, удаление, перенос между группами, заявки, результаты и массовые операции используют тот же механизм. Если изменились состав или порядок, обновляются соответствующие хранилища групп; уже полученные блоки используются повторно. Пустой, неполный или изменившийся во время чтения кеш имеет запасной путь обновления.
- Старые ответы после смены выборки не устанавливаются. До согласования загруженных групп действия недоступны. Серверные проверки версий, атомарность и бизнес-правила сохранены; данные не подменяются неподтверждёнными оптимистическими значениями.
- При смене дочерней группировки повторно используются небольшие итоги родительских групп строго в той же версии данных. Состав, порядок и число дочерних строк пересчитываются. Полные карточки в этот кеш не попадают.
- Устранены лишняя загрузка подсказок закрываемой формы, глобальный поиск дубликатов при обычном пересчёте одной линии и два сканирования всех стыков при проверке связанных линий. Неоднозначные старые ключи с Unicode-пробелами по краям сохраняют полный поиск. Узкое чтение участников групп сохраняет декодирование полей из схемы, сокращая обработку вложенных соединений.
- Руководство пользователя обновлено. Новых ограничений пользовательских операций нет; пакет из 32 блоков — размер одного транспортного запроса, большие кеши читаются частями с общей версией.

## Схема и локальные данные

Миграция `0051_black_frog_thor.sql` сгенерирована из Drizzle-схемы через `pnpm db:generate` и содержит только создание индекса нормализованных проекта/шифра/линии. Нормализация совпадает с прежней проверкой, включая Unicode-пробелы. Проверены окончательный SQL и фактическое выражение в PostgreSQL. Два предварительных варианта генерации отклонены до применения.

Миграция применена на main к проверенной локальной `localhost:5432/welding_tracker`. Контрольная сумма всех 77 рабочих стыков и количества связанных записей совпали до/после. Штатная подготовка выпуска дополнительно инициализировала ранее пустое состояние ПСТО двух локальных программ линий; статус подготовки — готово, предупреждений нет. Фикстуры и нагрузка работали только в изолированной `127.0.0.1:5432/welding_tracker_e2e`. Для будущего выпуска потребуется эта миграция; удалённое применение сейчас не разрешено.
