# Безопасность и сохранность данных — 24 ноября 2026

Цель проверки — предупредить посторонний доступ, утечку и потерю данных. Исходное состояние — коммит `f8fabb7c`. По уточнению пользователя исправления выполнены в локальном проекте. Прод, его журналы, настройки и данные в этой работе не открывались.

## Что исправлено локально

Повторная проверка сравнила скорость с прежним выпуском, подтвердила совместимость 17 шаблонов из локального резерва и привела к трём исправлениям. Они сохраняют параллельные загрузки шаблонов, выбор стыков при асинхронном поиске и даты неизменённых общих документов ПСТО и ТВМТ. Результаты описаны в [отчёте о совместимости и скорости](security-regression-and-performance-2026-11-24.md).

- PostgreSQL уже переведён на `127.0.0.1:5432`. До применения проверено отсутствие активных операций. После краткого перезапуска совпали существующий том, идентификатор кластера и OID рабочей БД. В Vite закрыты каталоги резервов, рабочих файлов, результатов и внутренней документации. Обычный контрольный модуль вернулся с HTTP 200, одинаковые синтетические файлы в трёх закрытых каталогах через оба способа чтения получили 403. Известный пример из 42 записей также исключён из раздачи Vite и контекста Docker.
- Отчёты и PDF передают клиенту только специально предназначенные ему сообщения. Для остальных ошибок возвращается код события. Диагностика очистки, сохранения шаблона и пересчёта диспетчера больше не выводит исходную ошибку. При чтении старых записей ошибок фонового диспетчера внутренний текст также скрывается.
- При загрузке Excel сервер самостоятельно читает настоящую книгу, определяет листы и поля, проверяет привязки конструктора и побайтно сверяет сохранённую копию перед публикацией. Повреждённая книга, неверная привязка или порча одного байта в хранилище сохраняют предыдущую рабочую версию. Для разбора используются отдельный процесс, ограничение времени и памяти и один одновременный разбор шаблона. Предел входного файла — 32 МБ. По заголовкам архива локального резерва выпуска самый большой из 17 шаблонов занимает 36 721 байт. Правило описано в справке приложения.
- Ограничитель частоты входа действует перед чтением тела запроса. И при указанном размере, и при передаче по частям принимается до 16 КиБ. Настройка доверия к прокси сохранена.
- Linux-образ проверяет SHA-512 архива pnpm по существующему lock-файлу. Рабочий процесс запускается с UID 1000. **Перед будущим выпуском** нужно проверить права на уже существующем постоянном томе шаблонов. Локальная проверка чистого тома не подтверждает права продового. [Условия выпуска](../README.md)
- Нагрузочный скрипт больше не очищает таблицы. Он проверяет фактическую БД, блокирует таблицы на время проверки и заполняет их одной транзакцией. В отдельном PostgreSQL после миграций успешно созданы 200 тестовых стыков. Повтор отклонён, контрольная сумма полного дампа данных, включая последовательности, совпала до и после повтора.

**Проверка исправлений.** Проверка типов и локальная сборка прошли. Из 8 590 модульных проверок прошли 8 587, три штатно пропущены. Пройдены 24 интеграционных и браузерных сценария в Chrome. Проверены обычный вход и выход через Nitro и Better Auth, восстановление и замена шаблонов, права на столбцы, выгрузки и операции со схемой. В финальном Linux-образе без внешней сети проверены UID 1000, ответ liveness, запись на свежий одноразовый том и чтение синтетических XLS и XLSX изолированным обработчиком. Миграции для исправлений не нужны.

В WebKit во время перезагрузки страницы дважды возникало необработанное исключение чтения PDF, хотя проверки сохранённых точек и редакций проходили. Старый локальный образ прошёл тот же сценарий четыре раза. Просмотрщик теперь завершает чтение при уходе со страницы и сохраняет его при помещении страницы в браузерный кеш переходов. После изменения прошли два отдельных повтора и все 10 выбранных сценариев WebKit. Повторные проверки Chrome охватили PDF, вход и выход. Для затронутых компонентов и библиотек схем повторно прошли 85 модульных проверок.

## Какие условия остаются

Реквизиты локальной разработки остаются общими для локальных инструментов. Для входа через прокси сохраняется общий лимит, пока оператор не подтвердит доверенную цепочку передачи IP. Независимое восстановление актуальных PDF из резерва продового S3 не проверялось. Отдельный хеш каждой PDF-редакции в БД и постоянная история изменения разметки остаются предложениями по целостности и прослеживаемости. Происхождение примера в истории Git может подтвердить владелец данных. Для применения исправлений приложения на проде нужен отдельный выпуск.

## Что может исчезнуть или измениться

- **Сохранённые стыки и документы.** В проверенных фоновых задачах и коде приложения не найдено удаления рабочих стыков, документов или действующих PDF по возрасту. В 06:30 проверяется необходимость пересчёта диспетчера. После удаления стыков очистка документов затрагивает связанные документы, оставшиеся без позиций. При выходе или смене прав приложение также очищает приватное состояние браузера, включая несохранённые данные вкладки. Эта очистка не удаляет записи из БД. [Очистка документов](../src/server/generated-document-cleanup.ts) · [Расписание](../src/server/dispatcher-prewarm-plugin.ts) · [Данные браузера](../src/lib/user-storage.ts)
- **История схем.** Удаление редакции каскадно удаляет её точки, размеры и аннотации. Эти таблицы не включены в общий журнал изменений. Квитанции операций содержат автора и служат для безопасного повтора, но после семи дней подлежат очистке. Поэтому задним числом может оказаться невозможно установить, кто перенёс точку или удалил редакцию и какие данные были до изменения. Стоит записывать существенные изменения схем в постоянный журнал в той же транзакции. Для самих PDF очистка проверяет состояние файла и отсутствие ссылки на него из редакций. [Работа с редакциями](../src/server/line-scheme-write.ts) · [Общий журнал](../src/server/audited-database.ts) · [Очистка](../src/server/line-scheme-file-cleanup.ts)
- **Целостность и восстановление PDF.** При загрузке S3 получает контрольные суммы и запрет перезаписи. При чтении приложение сверяет размер. Независимый SHA-256 в записи редакции не сохраняется, поэтому подмена файла той же длины вне приложения может остаться незамеченной. Дамп БД сохраняет геометрию и привязки. Сами PDF по решению пользователя исключены из локальных копий выпусков. Восстановление комплекта из тестового S3 ранее проверяли, восстановимость отдельной копии действующих и архивных PDF прода остаётся неподтверждённой. Для новых редакций стоит сохранять хеш в БД и сверять при восстановлении. [Чтение PDF](../src/server/line-scheme-file-response.ts) · [Запись в S3](../src/server/line-scheme-s3.ts) · [Пределы проверки резервов](s3-backup-restore-2026-11-11.md)
- **Нагрузочный скрипт.** При подготовке набора на 200 000 стыков он очищает все таблицы схемы public. Проверяет ожидаемое имя локальной БД, но не проверяет, что сам создал пустую БД и владеет именно этим экземпляром. Ошибка оператора при подготовке данных может уничтожить ранее существовавшее содержимое. Скрипт в этом аудите не запускался. Стоит применить защиту штатного E2E-раннера с проверкой фактической БД и её идентификатора. [Скрипт](../scripts/benchmark-system-scale.ts) · [Образец защиты](../e2e/database.ts)

## Защита от постороннего доступа

Сверены политики серверных операций, отдельные HTTP-маршруты, сессии Better Auth 1.7.14, права на поля и выгрузки, построение SQL и вывод пользовательского текста в отчётах. У серверных функций проверяются источник запроса и права. Неизвестная политика отклоняется. Для предпросмотра документов задан запрет выполнения скриптов. В локальной сборке проверены привязки 210 серверных функций. Полную матрицу всех ролей для каждой функции этот подсчёт не покрывает. [Политики](../src/server/access-operation-policy.ts) · [Защита запросов](../src/start.ts) · [Предпросмотр](../src/lib/document-preview-frame.ts) · [Сессии Better Auth](https://better-auth.com/docs/concepts/session-management)

Кроме первоочередных проблем, проверка выявила ещё три риска.

- Обработчик входа разбирает тело запроса до применения ограничителя частоты. При отключённом доверии к прокси действует общий лимит входа для пользователей, поэтому один источник может затруднить вход остальным. Нужны небольшой предел тела запроса до разбора и проверенная схема ограничения частоты на входе. Фактические ограничения продового прокси не исследовались. [Вход](../src/server/auth.ts)
- Установщик пакетного менеджера при сборке скачивается без независимой проверки хеша. В локальном образе выпуска пользователь контейнера по умолчанию — root. Стоит закрепить и проверять установщик и запускать приложение с минимальными правами, предварительно проверив права записи в каталог шаблонов. [Dockerfile](../Dockerfile)
- В Git есть пример из 42 записей сварки. Происхождение записей по репозиторию установить не удалось. 22 длинных идентификатора линий и изометрий из этого файла не обнаружены в текущей публичной сборке. Владельцу данных стоит подтвердить, допустимо ли хранение примера в Git. [Данные примера](../src/data/seed-welds.json)
