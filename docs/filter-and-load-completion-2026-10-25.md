# Фильтры и восемь нагрузочных профилей — 25.10.2026

**Два тяжёлых фильтра и восемь нагрузочных профилей выполнены; общая регрессия и адресные повторы завершены.** Оставшиеся задержки и отдельный дефект быстрых клавиатурных команд перечислены ниже. Работа локальная, без коммита, push, production-действий и запуска большого системного аудита. Схема БД не менялась, новых миграций нет.

## Решения и оставшиеся ограничения

- По последнему решению пользователя **вся прежняя печать сохранена и восстановлена**: отчёты, статистика, программа линий, PDF руководства, горячие клавиши и настройки Excel. Обсуждавшееся удаление отменено. Общий механизм достаточно небольшой; усложнять его не потребовалось.
- Сохранены существующие пределы: 100 строк предпросмотра на странице, 1000 строк для встроенной печати, 10000 строк для полного табличного вывода. Excel содержит весь подготовленный отчёт. Операции документов ограничиваются пакетами до 200 документов / 60000 позиций с прежними ограничениями размера и повторной проверкой перед применением. Новых ограничений не введено.
- При полном пересчёте диспетчера на 200000 стыков поиск ожидает около **19–21 с**, холодный первый запуск — **26–27 с**. Обычный прогретый поиск значительно быстрее. Барьер свежести сохранён; эта остаточная задержка — тема отдельно запрошенного системного аудита, а не основание выдавать старые статусы за новые.
- При непрерывной смешанной работе пяти клиентов отдельные сценарии отчёта/редактирования занимали до 15,4 с. Первый составной сценарий документов и клейм — 30,5 с, последующие — до 8,6 с. Это время полного пользовательского сценария, не одного SQL или сохранения; успешная проверка не означает мгновенный интерфейс под нагрузкой.
- **Отдельный неисправленный дефект AG Grid 36.2.0:** при быстром PageDown → End в программе линий отложенный обработчик PageDown возвращает фокус с последней строки на предыдущую страницу. Этот механизм не менялся в данной задаче; случай записан для отдельного аудита AG Grid. Проверка обычных последовательных команд теперь ждёт стабильного фокуса/прокрутки после PageDown и строго проверяет End/Home. Её успех не подтверждает исправление перекрывающихся команд. Запись событий и воспроизведение: `keyboard-overlap.log` и `keyboard-overlap-artifacts/`.
- Результаты локальные. Нагрузочные контейнерные профили: **4 CPU / 4 ГиБ без swap** для приложения; PostgreSQL и браузеры измеряются отдельно. Старые 2 CPU / 2 ГБ пользователь больше не считает целевым условием. Конфигурация production этим не проверялась.

## Исправления

1. Схемы РК: компактный поиск по массиву порогов вместо большого дерева SQL, однократный разбор координат. Исправлена ложная подпись «Требуется проверить» при старых повторяющихся диаметрах. Версия производного кэша увеличена 5 → 6.
2. Текущий цикл ПСТО/ТВМТ: один выбор повторного цикла, устранены повторные вычисления ожидания и ненужный анализ брака завершённого цикла. Сохранены приоритет выполненной истории и пустые поля повторов.
3. Общий фильтр нескольких значений: одно сравнение ANY вместо копирования тяжёлого выражения для каждого флажка. Проверены соседние расчётные поля, пустые значения, CRLF/BOM и большой множественный выбор.
4. Реестры документов: метаданные разбираются в JSON один раз; версия индексированного реестра использует существующие ID и версию строки. Ручные и производные истории продолжают учитывать связанные данные полностью. Изменение метаданных, специалистов и состава инвалидирует прежнюю версию.
5. Конкурентное чтение журнала/ЛНК/ПСТО: количество, строки и связи читаются в одной короткой read-only транзакции с согласованным снимком. Непрерывные импорты больше не заставляют отбрасывать уже согласованный ответ. Последующие обращения со старой версией по-прежнему отклоняются. Новых очередей, блокировок записи и схем БД нет.
6. Готовность AG Grid публикуется после установки строк; «Текущая версия» отключена во время обновления. Это устраняет окно, когда контекстное меню уже доступно, но строки ещё заменяются. Анимация результата тоже ожидает готовности интерфейса, без опроса и новых таймеров. Ошибка преждевременного запуска анимации воспроизведена отдельной регрессией до исправления. Руководство обновлено.

Регрессии воспроизвели до исправления рост SQL при множественном выборе/большой таблице РК, ошибку повторяющихся порогов и отказ чтения при конкурентном сохранении. Измеритель нагрузки отдельно исправлен для штатно отменённых POST-чтений и переходов между страницами; реальные ошибки и отмены записей остаются ошибками.

Профиль реестров проверяет метаданные и реальные связи, а не хранение 600000 физических файлов Excel. Между исходным и итоговым замером уточнены даты событий в фикстуре при том же числе документов и связей; сравнение времени реестров не является строго идентичным повтором данных. Сумма процессов браузера не равна памяти одной вкладки. Контейнерные результаты нельзя считать совокупным потреблением сервера с PostgreSQL и браузерами.

## Итоговая проверка и материалы

- Типизация приложения и изменённых E2E: пройдена. После последней правки анимации полный unit-набор: **634 файла, 6399 тестов пройдены, 2 пропущены**. Production build: пройден, 161 серверная функция и ссылки RPC проверены.
- Общий Chromium E2E-набор: **698 пройдены, 3 сбоя, 26 пропущены** за 49,5 мин. Разобраны все три: старый тест реестра ошибочно считал общий размер при явном выборе; анимация начиналась до готовности интерфейса; клавиатурные команды перекрывались. В тесте реестра дополнительно проверяются точные ID и удаление уходящих DOM-строк до измерения постоянного размера. Пропуски — отдельные нагрузочные/диагностические режимы; восемь согласованных профилей выполнены отдельно.
- На итоговой сборке: **21/21** адресных проверок интерфейса (семь сценариев по три раза), **23/23** остальных проверок реестра и отдельно **1/1** старого профиля на 200000 стыков; Excel 10000 × 111 и печать 1000 × 111 прошли. Эти повторы закрывают обычные сценарии трёх сбоев; быстрый клавиатурный случай остаётся указанным выше дефектом. После небольшой последней правки ожидания анимации весь 49-минутный набор повторно не запускался; повторены все три потребителя общего механизма анимации и готовность трёх отчётов.
