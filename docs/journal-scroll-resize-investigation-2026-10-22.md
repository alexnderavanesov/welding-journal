# Прокрутка и ширина раскрытых групп — 22.10.2026

## Повтор после разблокировки Mac: объединение событий

**Установленные Safari и Chrome проверены; объединение не включено в приложение из-за ухудшения обычного resize Safari.** Проверены два общих варианта: одно обновление в RAF и немедленное первое движение с объединением следующих. Ветка по браузеру и изменения AG Grid не добавлялись. Все 1792 файла приложения и тестов побайтно совпадают с началом этого повторного прохода; прежние незакоммиченные изменения сохранены.

Шесть отдельных локальных запусков, всего 38 жестов: Safari 26.6.2 и Chrome 155.0.8059.85, обычный CPU, прежняя production-сборка, 111 столбцов, три раскрытых уровня. Каждый жест — 240 команд расширения на 180 px и возврата; все конечные ширины равны 200 px. Все 19 жестов Safari прошли в активном видимом окне. Фикстуры только в одноразовой локальной БД. Внутри каждой серии исходный вариант и опыт переключались на одной странице без смены ресурсов/данных/размера окна. Safari: окно 1600×1050; Chrome: viewport 1600×937, DPR 2.

Подтверждающая серия: 350 стыков, шаг команды 8 мс, отдельный исходный прогрев, затем три пары «исходный → RAF». Ниже медианы трёх повторов; меньше — лучше.

| Диагностическая метрика | Safari: исходный → RAF | Chrome: исходный → RAF |
| --- | ---: | ---: |
| p95 интервала RAF | 27 → 30 мс | 17,8 → 17,4 мс |
| Средний интервал RAF | 24,39 → 27,52 мс | 16,68 → 16,64 мс |
| Изменения ширины заголовка за жест | 240 → 80 | 232 → 114 |
| p95 ожидания последнего события до применения ширины | 0 → 16 мс | 0 → 1,6 мс |

В подтверждающей серии RPC — 0. RAF не равен измеренному физическому FPS экрана. Ожидание события измерено до изменения DOM, это не полная задержка до появления пикселей. Первые смещения 2–3 px штатный AG Grid пропускает до достижения порога начала перетаскивания; итоговая ширина не теряется. Драйверы по-разному доставляют ввод: Chrome частично объединяет исходные команды, Safari доставил все 240. Абсолютное время выполнения команд не считается ускорением пользовательского жеста.

На более быстром жесте (шаг 4 мс, 18 стыков с короткими вложенными группами, порядок исходный/RAF/немедленный/немедленный/RAF/исходный) p95 Safari улучшился с 37/43 до 32/31 мс, Chrome — с 17,8/17,8 до 16,8/16,9 мс. Но выигрыш этого случая не компенсирует подтверждённое ухудшение обычного движения. Вариант с немедленным первым откликом также не устранил компромисс: в первой обычной серии Safari p95 30/30 мс при 162 обновлениях вместо 240.

**Решение:** сохранить текущую обработку изменения ширины. Экспериментальный перехват/повторная отправка PointerEvent удалены вместе с временными измерительными вставками; до проверки всех штатных жестов (Shift, группы заголовков, отмена и др.) внедрение не дошло, поскольку вариант не прошёл критерий производительности. Это не доказательство невозможности дальнейшего ускорения Safari: следующий предмет исследования — стоимость одного перерасчёта/отрисовки, а не только число событий.

Подробности сохранены вне репозитория: `../welding-journal-local-measurements/2026-10-22-resize-coalescing/`, 15 файлов / 243741 байт без manifest; SHA-256 копий проверен. Там результаты, логи, временный измеритель, патч опыта и исходные хэши. В проекте остаётся только этот компактный результат. Полная предкоммитная проверка повторно не запускалась: итоговых изменений приложения/тестов/схемы нет. Одноразовая БД удалена, сервер 3000 сохранён; без агентов, коммита, push и действий на production.

## Предыдущий проход — исторический результат

**Нового подтверждённого ускорения для обоих браузеров нет; изменения приложения не оставлены.** Исходники и тесты восстановлены побайтно к началу этого прохода, прежние незакоммиченные доработки сохранены. Установленный Safari успешно измерен до экспериментов; два сравнительных запуска исключены из-за скрытого окна, затем управление экраном подтвердило блокировку Mac. По прежнему разрешению пользователя работа продолжена в WebKit. Полного сравнения установленного Safari до/после нет.

## Проверенные варианты

- **Пропуск принудительной отрисовки при горизонтальном скролле.** Старый обработчик завершает очередь AG Grid/React также при чисто горизонтальном движении. Узкий вариант оставлял принудительное завершение только при изменении вертикальной позиции. Новая модульная проверка воспроизвела старое поведение и прошла после изменения. Но выигрыш Chrome не подтвердился в WebKit: вариант отклонён, связанные исходники и временный тест восстановлены.
- **Оформление групп.** Замена внутренней тени цветной полосой и отдельный графический слой для закреплённых групп проверены только на тестовой странице, в прямом и обратном порядке. Разница p95 около 1 мс не даёт устойчивого выигрыша; варианты не включены.
- **Объединение движений указателя.** В диагностике WebKit за интервал между RAF приходило до 3–4 событий; AG Grid менял ширину на каждое. В Chrome — одно событие. Эксперимент снизил число обновлений WebKit с 240 до 52/75 на те же 240 команд драйвера, но p95 остался 28 мс. В Chrome сохранились 240 обновлений, без существенного изменения p95. Опыт использует повторную отправку PointerEvent и не включён в приложение: задержка относительно физического указателя, полная совместимость жестов и результат установленного Safari не подтверждены. Сокращение времени выполнения команд драйвера не считается ускорением реального пользовательского жеста.

Сохранён текущий механизм прокрутки и ширины. Перехват указателя, изменения библиотеки, отдельный код Safari и новые задержки в приложение не добавлялись.
