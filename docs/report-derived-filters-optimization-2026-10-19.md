Последующие исправления, полный браузерный прогон и свежие замеры окончательного кода — в [предкоммитной проверке](precommit-audit-2026-10-19-lnk-filters.md). Ниже сохранены результаты этапа оптимизации.

Отбор ЛНК, ПСТО и журнала выполняется в SQL до загрузки страницы. Устранён прежний обход всей выборки в приложении для основных методов НК, НК до ТО, оснований, WDI, схем РК и сводки циклов ПСТО. **Оставшиеся ограничения:** первый сложный фильтр сводки ПСТО занимает около 3,3 с; схема РК с большой настроенной таблицей — около 3,5 с. Точные COUNT/DISTINCT могут обходить много строк внутри БД. Отдельный контекст статусов рабочих окон/вывода, чтение общего состояния диспетчера (около 9 МБ в измеренном профиле) и его фоновый пересчёт сохранены; расчётные фильтры больше не вызывают прежнюю глобальную сборку карточек.

## Что сохранено и исправлено

Кэш хранит только ID и версии одной страницы; учитывает сортировку, публикацию задач и отпечаток необходимых настроек. Карточки перечитываются с проверкой версии, устаревший результат не публикуется под новой ревизией. Большая таблица схем РК проверяет варианты только выбранного размера.

Сохранены факты и история, различия между подписью ячейки и значением фильтра, права, проверки действий, снимок и предел 500 строк массового заполнения, прежняя область ограничения полного вывода в 10000 строк. По подтверждённому решению пользователя обычные и расчётные фильтры используют одинаковый порядок страниц; сортировка по заголовку сохранена, руководство обновлено.

Исправлены пустые варианты НК до ТО в журнале и пропуск строки ПСТО с историей только в повторе. Сводка цикла в ответе страницы также учитывает загруженные повторы. При полном E2E обнаружено сжатие поиска программы линий на ширине 1000 px: кнопка настройки вида теперь компактна на этой ширине; руководство дополнено.

## Скорость до и после

Одна машина, одинаковые изолированные fixtures на **200000 стыков**. Основная таблица измеряет серверную загрузку страницы из 100 строк без отдельного запроса итогов. Холодный запрос — очищен кэш расчётов, но не PostgreSQL; медиана трёх повторов. Повторные/обычные — по 20 запросов.

| Фильтр / сценарий | До | После |
| --- | ---: | ---: |
| Результат РК, холодный | 4,99 с | **0,16 с** |
| НК до ТО, холодный | 5,00 с | **0,71 с** |
| Основания, холодный | 4,89 с | **0,24 с** |
| Схема РК без таблицы, холодный | 5,05 с | **0,70 с** |
| Сводка циклов ПСТО, холодный | 6,68 с | **3,29 с** |
| WDI: формула / таблица, повторный | 2,46 / 2,46 с | **0,105 / 0,106 с** |
| Обычная страница ЛНК | 242 мс | **242 мс** |
| Обычная страница журнала, парное чередование | 181 мс | **183 мс** |
| Обычная страница ПСТО, парное чередование | 873 мс | **874 мс** |

p95 обычных страниц: ЛНК **248 → 249 мс**, журнал **234 → 235 мс**, ПСТО **882 → 908 мс**. Отдельные серии журнала дали неоднозначные медианы 182 → 229 мс; поэтому выполнено контрольное чередование версий на одной базе с изменением порядка каждой пары. Устойчивое замедление не подтвердилось. Сверены полные ответы; отличие ПСТО — исправленная сводка повтора, проверенная по фактам fixture.

Настроенная схема РК: типичная таблица **5,19 → 2,06 с**; 300 размеров × 4 варианта — **5,19 → 3,51 с** в одиночном стрессовом замере. Повторные запросы обеих — около 0,107 с. Пять прогретых читателей: медиана **517 → 495 мс**, p95 **526 → 513 мс**.

Для холодного РК: SQL **26 → 19**, передача из БД **124,7 → 9,1 МБ**, максимальный набор строк одного ответа БД **200000 → 750** с учётом связей. Размер ответа из 100 строк одинаков — 207673 байта. CPU: **5610 → 122 мс**; RSS **3,14 → 1,37 ГБ** включает подготовку fixtures, это не оценка памяти production.

Дополнительно проверены масштабы 1000/10000 и одна линия из 200000 стыков с длинными текстами: страница 1000 строк **5,92 → 0,33 с**, поздняя страница **5,69 → 0,79 с**, варианты WDI **15–16 → 0,6–0,7 с**, вывод 500 строк **0,58 → 0,28 с**. Изучены планы SQL и существующие индексы. Пять чтений с записью fixture проверяют актуальность отбора, но не измеряют полный пользовательский цикл сохранения/пересчёта диспетчера.
