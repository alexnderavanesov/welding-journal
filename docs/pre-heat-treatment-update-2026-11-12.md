# НК до ТО — реализация дополнений 12.11.2026

Реализован согласованный объём локально в `main`. Основание: прямое поручение пользователя 12.11.2026; требования в [плане](pre-heat-treatment-modes-plan-2026-11-06.md). Коммит, push и изменения production не выполнялись.

## Поведение

- В ЛНК появились кнопка **«НК до ТО»** над таблицей и одноимённое меню ПКМ. Команды: поставить отметку, отдельно заполнить недостающее как «Годен», снять отметку. Постановка предлагает оставить комплект пустым либо поставить отметку и заполнить его одним сохранением.
- Постановка/снятие охватывают показанные физические цепочки с R/W и одноимёнными повторениями; повторный выбор звеньев не дублирует цепочку. Стороны катушки самостоятельны. Отдельное заполнение охватывает только выбранные применимые записи с отметкой.
- Снятие показывает данные и последствия для общих документов. Текущий предварительный «Ремонт»/«Вырез» блокирует операцию; основной брак сам по себе не блокирует. Сохраняются чужие позиции, другие этапы и цепочки. Проверки версии, прав и атомарности сохранены; массовые сохранения поддерживают восстановление подтверждения после неопределённого сетевого ответа.
- Столбец **«НК до ТО»** добавлен после «Назначение ПСТО» в СВЖ, ПСТО и ЛНК, включая старые сохранённые раскладки. Он показывает необходимость этапа, фильтруется и доступен в отчётах. Обычное редактирование/импорт отметку не меняют.
- Новый независимый стык можно создать сразу с отметкой, если выбранная в черновике линия предусматривает ПСТО. При смене её идентичности ручной выбор сбрасывается. Новые независимые стыки/стороны катушки по умолчанию без отметки; R/W наследуют её. Перенос сохранённой цепочки не удаляет историю.
- Выбор режима убран. Устаревшие значения настроек больше не включают полный режим. Подготовка общего комплекта учитывает зависимости **заявка → ВИК → ПВК → РК/УЗК**, сохраняя проверки дат, результатов и последовательности.
- Обновлены встроенное руководство, подписи журнала активности и версия расчёта диспетчера: **88**.

## Данные и выпуск

Уточнение интерфейса от 12.11: кнопка «НК до ТО» перемещена после «Официальность». Столбец во всех трёх разделах показывает «—» для неприменимого этапа, пустую ячейку для выключенной отметки при ПСТО и «Да» для включённой отметки. Есть подсказки и отдельные понятные названия состояний в фильтре. Сохранённая отметка без текущего ПСТО остаётся «Да» с пояснением. Копирование, предпросмотр и Excel используют ту же разницу; фильтры SQL и клиента согласованы. Изменение не переписывает данные и не требует дополнительной подготовки БД; версия ключей сохранённого кэша отчётных фильтров обновлена, чтобы исключить старые результаты отбора.

Новой SQL-миграции нет: используется существующее поле. Явная подготовка выпуска записывает маркер `maintenance:pre-heat-treatment:selected:v1`. Для старого полного режима предварительно материализуются действовавшие требования, включая скрытые `false`; для выборочного режима сохраняются прежние отметки. Документы и результаты не меняются. Проверка готовности не допускает новую семантику без этого перехода.

Локально выполнена штатная подготовка данных для проверенной цели **localhost / welding_tracker**. Прежний режим был выборочным, изменённых отметок — 0. До/после совпали контрольные отпечатки всех **84 записей НК до ТО, 350 документов и 384 связей документов**. Всего стыков 114; прежние флаги сохранены.

Для будущего production-выпуска требуется штатная отдельно разрешённая подготовка данных с этим маркером. Production сейчас не изменялся.

## Проверка

- Ошибка общего заполнения сначала воспроизведена падающими регрессиями; после исправления проходят ВИК+ПВК+РК, ВИК+ПВК+УЗК и все четыре метода. Реальное противоречие дат продолжает блокировать запись.
- Проверены сохранение нового стыка, наследование, выключенный независимый стык, смена линии, состав массовых цепочек, общие/пустые документы, предварительный брак, устаревший просмотр, одновременное сохранение, откат, сохранность существующих результатов и выборочные фильтры. Старые сценарии переведены с неявного полного режима на явные требования стыков.
- В Chrome проверены все 22 сценария тематического набора; после уточнения селекторов два сценария ПКМ повторены отдельно. В готовой сборке дополнительно прошли 5 проверок Chrome, включая переход старых настроек. В WebKit готовой сборки прошли все 22 сценария.
- В массовом просмотре чтение линий, цепочек и документов объединено. Для 1 и 500 независимых цепочек одной линии — **29 запросов** в обоих случаях; 500 цепочек — около **0,2 с** локально. Это ограниченная проверка нового действия, не системный аудит или гарантия production-производительности.
- Исходная реализация: полный модульный набор — **7918 прошли, 3 пропущены, ошибок нет**. Прошли проверка TypeScript, сборка и проверки серверного манифеста/изоляции браузерных модулей. Проверка сборки выявила попадание серверного динамического импорта в клиентский артефакт; серверная граница исправлена и повторно проверена.
- Последующее уточнение столбца: **166 профильных модульных проверок**, TypeScript и итоговая сборка с обеими проверками артефактов прошли. Три состояния, подсказки, фильтрация и поиск по понятным названиям проверены в СВЖ/ЛНК/ПСТО в Chrome и WebKit. Прочерк выровнен слева; окончательное оформление повторно проверено в Chrome. В изменённом SQL добавлен только скалярный `CASE` по полям той же записи, новых запросов/соединений таблиц или построчных обращений нет; большой нагрузочный аудит не запускался.

Отложенные идеи остаются в [списке задач с неопределённой полезностью](tasks-to-consider.md); их реализация не входила в эту работу.
