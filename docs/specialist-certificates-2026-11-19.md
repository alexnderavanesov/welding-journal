# Удостоверения специалистов — 19.11.2026

Реализовано локально по согласованному дополнению к [плану специалистов](specialists-plan-2026-10-12.md). Коммит, push и production-операции не выполнялись.

Последующая полная проверка всего пакета, исправления сохранения/прав и измерения 10 000 документов — в [итоге 20.11.2026](precommit-audit-2026-11-20.md). Ниже сохранён объём проверки на этапе первоначальной реализации.

В карточке общие ФИО, тип и клеймо, затем раскрывающиеся удостоверения с собственными номером, сроком и методами. Использованы общие поля, кнопки и галочки приложения; проверены широкий и узкий экран, сворачивание, клавиатура, Escape и возврат фокуса.

Правила:

- Выбор по дате **заключения** и методу: подходящее удостоверение со сроком имеет приоритет над удостоверением без дат. Границы включительны.
- Заполняются обе даты либо ни одной. Для одного метода запрещены пересечение периодов и несколько удостоверений без дат. Разные методы могут иметь пересекающиеся сроки. Для термиста применяется ПСТО.
- Нет подходящего удостоверения — нет нового назначения. Для назначения нужна дата документа; очистка прежней роли допустима и без неё.
- При массовом назначении человек должен подходить для всех выбранных документов; номер сохраняется отдельно для каждого. Поиск учитывает все номера, проверка допуска применяется в SQL до ограничения списка первыми 100 карточками.
- Старые карточки читаются как одно удостоверение без дат. Снимки старых назначений не меняются автоматически. Явное переназначение старого документа использует новые правила.
- Новое назначение хранит дату проверки. Смена даты повторно проверяет допуск; смена номера обычного заключения требует подтверждения, ФИО/клеймо сохраняются. У послойного заключения дата следует за датой сварки, проверка и подбор номера происходят при её изменении. Ошибка отменяет всю транзакцию.
- Недопустимые запомненные пары не подставляются. Сохраняются необязательность ролей, архив, версии карточек/документов и защита массовых операций от частичного сохранения.

Хранение: nullable `specialists.certificates` JSONB без переноса старых данных; прежние поля остаются совместимым представлением первого номера и объединённых методов. Сгенерирована миграция **0074_milky_cyclops.sql** и применена только к локальной `127.0.0.1:5432/welding_tracker` на `main`. До и после миграции совпали количества и контрольные суммы прежних полей 5 карточек и назначений 321 документа. Для production миграция остаётся частью отдельно разрешённого выпуска по существующему процессу.

Проверки:

- TypeScript, сборка, проверки 202 server functions / RPC и клиентского кода — успешно.
- Полный unit-прогон: 830 файлов прошли; два PDF-файла первоначально упёрлись в запрет sandbox на `ps`. Их отдельный повтор с доступом к памяти локального дочернего процесса прошёл: 38 тестов, S3 замокирован. После окончательных правок затронутого кода — **195 тестов в 24 файлах**, успешно.
- Chrome: **20 разных сценариев в серии прогонов**, включая создание и редактирование карточек, выбор за пределами первых 100 неподходящих специалистов, разные номера в пакетном назначении, смену даты/подтверждение/откат, старую историю, послойные документы, реальные Excel ВИК/ПСТО, создание НК до ТО и ПСТО, объединение, удаление состава и конкурентные назначения. WebKit: **4 затронутых сценария**, успешно.
- Скриншоты карточки на широком и узком экранах просмотрены. Найденные ошибка SQL-приоритета операторов и потеря фокуса при StrictMode-повторе эффекта исправлены; добавлены регрессии.
- Сохранились ограничения запросов: одна общая загрузка выбора для 1000 документов, два пакетных чтения и одна запись для назначения 1/10000 документов. Это проверка количества запросов, не новое измерение задержек на большом наборе данных.

Все fixtures и браузерные проверки использовали отдельную локальную `welding_tracker_e2e`; runner проверял изоляцию и удалял принадлежащую ему базу после прогона. Руководство пользователя обновлено. Новый полный системный/нагрузочный аудит не проводился; ранее отложенные задачи этим изменением не возобновлялись.
