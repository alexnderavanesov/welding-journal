# Предкоммитная проверка 24.11.2026

**Проверка завершена. Пакет готов к локальному коммиту.** Проверен весь набор изменений на `main` относительно `3510c476`. Исправлены повторное создание стыков после обрыва связи, ошибки проверки и предпросмотра Excel, лишние чтения журнала и документов, а также отрисовка большой сводки закрытий. Браузерные и нагрузочные проверки выполнялись в изолированных локальных базах. Временные базы и тестовые серверы закрыты.

## Закрытия работ и статистика

- Закрытый фильтр закрытий продолжал загружать варианты при изменении поиска журнала. Воспроизведён лишний запрос. Фильтр теперь загружает значения при открытии и учитывает изменившуюся выборку при повторном открытии.
- Изменение расценки сбрасывало результаты статистики, которая эту расценку не использует. Теперь сохранение закрытия переносит только актуальный результат той же версии расчёта. Проверены соседние изменения исходных данных, устаревшая версия и сброс отчёта, который действительно содержит закрытия. Для пользователей с закрытым просмотром убрана выборка позиций в SQL журнала. В полинейной сводке убрана отдельная выборка шифров, для которой отсутствует поле выбора.
- Пустые значения и введённые вручную слова «Без кода» и «Без КС3» различимы в фильтрах и сводках. Проверены сохранение исторических работ до ТО, фильтрация одной и той же позиции по трём полям, права, конфликты массовой записи, история и соответствие отобранных строк отчёту и Excel.
- При 10 000 разных кодов одна сгруппированная сводка создавала 80 018 элементов в браузере. После изменения длинная таблица отрисовывает видимые строки с небольшим запасом. На том же сценарии открытие и переход к концу заняли **1 647 → 391 мс**. После прокрутки браузер содержал 254 элемента. Для всех трёх сводок проверен доступ к последней строке, для итоговой выборки — переход по Enter к правильному стыку. Пагинация не требуется.

## Excel и разграничение доступа

**Новые стыки.** Проверены реальный шаблон, комбинированные ошибки ячеек, сохранение только выбранных валидных строк, отзыв и возврат права импорта между предпросмотром и сохранением. Сервер повторно проверяет права и квалификацию. Введённые в книгу поля закрытия работ не создают позиции закрытия. Исправлен ненужный запрос права на просмотр программы линий. Запрос для импорта отдаёт только проект, шифр, линию, категорию, группу и базовый процент.

По решению пользователя от 24.11 инженер с правом импорта может указать официальные клейма при закрытом справочнике. Сервер проверяет переданные сочетания параметров, возвращает ошибки с указанием поля и не передаёт карточки сварщиков. Для нескольких стыков с одинаковыми параметрами достаточно одной проверки. В реальном файле для одной строки одновременно распознаны неизвестное клеймо и неверная дата. Две остальные строки приняты. При отстранении сварщика после предпросмотра обе записи отклонены, после восстановления допуска обе сохранены.

На отдельном файле из 13 строк с включённым ДЛС проверены точные граничные даты, выход за срок, диаметры и толщины обеих сторон, порядок материалов, способ сварки и неизвестное клеймо. Три допустимые строки прошли, десять ошибочных получили ожидаемые номера строк Excel. Кнопка «Исправить ошибки» в отдельном примере очистила ошибочное клеймо и сохранила введённые материалы. Номер удостоверения из карточки в результат проверки не попал.

**Замена и массовое заполнение.** Проверены версии строк, частичные данные после объединения с хранящимися значениями, защита служебных полей и уже записанных закрытий. Неверная пара материалов при неизменных размерах и клейме отклонена. Исправление изометрии сохранило клеймо и материалы. Включение обязательного ДЛС после предпросмотра заблокировало пакет целиком. Удаление без отдельного права и удаление по устаревшему шаблону отклонены. По свежей подтверждённой замене удалён именно указанный стык, удаление связанного закрытия отражено в истории.

Два дефекта предпросмотра воспроизведены до исправления. Пустая строка листа сдвигала подсветку и переход к ошибке. Два действия для одного ID проходили предпросмотр, затем сервер отклонял сохранение. Теперь навигация использует фактический номер строки Excel, конфликтующие действия отмечаются по каждой строке, а исключённым строкам не соответствует версия в отправляемом массиве. Одноимённые стыки с разными ID проверены отдельно.

**Потеря ответа при создании.** В локальном Chrome сервер записал стык, после чего ответ до браузера не дошёл. Повторная кнопка создала второй стык. Исправление связывает попытку с пользователем и составом отправки, а результат сохраняется в транзакции со стыками. Проверены два одновременных одинаковых запроса и последующий повтор после разрыва связи. Получены те же ID, один стык и одна операция создания в истории. Из обычного импорта также убраны повторное чтение и блокировка уже подготовленной программы линии. Для 1 и 500 строк число SQL-запросов сохранения изменилось с 39 до 38 и с 44 до 43 соответственно.

При потере ответа окно теперь сообщает, что подтверждение не получено, и подсказывает повторить кнопку в этом же окне. При отказе по правам или допуску выводится причина отказа. Оба случая проверены в Chrome, потеря ответа также проверена в WebKit.

Отдельно проверена повторная загрузка того же файла через заново открытый диалог. Во время предпросмотра в базе оставался один стык. После нового подтверждения появились второй стык и вторая запись о создании в истории.
