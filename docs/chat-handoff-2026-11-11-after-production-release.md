- Две пары клейм — официальные/фактические «Клеймо 1/2», не слои. Для Т только первая пара; статистика факта 100% одному уникальному / 50–50 двум. Однородный У19 закрыт: D/T стороны меньшего диаметра, при равных D — меньшая T; 57×6 + 159×3 → D57/T6. Подбор ТК имеет отдельное правило.

## Правила нового чата

1. Пока только чтение контекста и обсуждение. **Никакой реализации, нового аудита, тестовых прогонов, миграций или production-операций до нового прямого поручения.** Разрешения завершённого выпуска не являются постоянными.
2. Не делать автоматический commit/push/deploy, reset/stash, смену ветки, новый worktree, остановку/запуск серверов. Сохранить данные, файлы и незакоммиченные документы. Новый чат — в этом же checkout/main; модель/настройки не менять. Без субагентов, если пользователь отдельно не согласует конкретную пользу.
3. Production — реальная рабочая система даже при `test` в URL. Справочник [production-links.md](production-links.md) не разрешает действий. БД Selectel `welding_journal` в приватной сети; старый Yandex URL локальной `.env` устарел. Чтение production не разрешает тесты, расчёты или скрытые изменения. Push main запускает автодеплой и требует отдельного согласования конкретного выпуска.
4. При отдельно разрешённой реализации действует постоянное разрешение **проверенных локальных миграций на main**: точный локальный host/db, сохранение данных, schema.ts → `pnpm db:generate` → просмотр → `pnpm db:migrate`. Не писать SQL вручную. Фикстуры/нагрузка/restore только в отдельной проверенной пустой локальной БД; не заменять основную. Производственные миграции — только новое отдельное разрешение и штатная `pnpm db:remote-migration` с выделенной переменной.
5. Для будущей auth-работы использовать официальные Better Auth MCP/skills и установленную версию, [согласованный план](authentication-and-access-plan-2026-10-29.md); это не поручение расширять auth. Новые пользовательские правила сопровождать руководством. Секреты не переносить в чат, документы или Git.
