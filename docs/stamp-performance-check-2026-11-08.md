# Плавность после сокращения клейм — 08.11.2026

В проверенных сценариях Chrome и WebKit новых устойчивых лагов после сокращения клейм не подтверждено. Найдена и исправлена лишняя работа форматирования чисел в статистике. Из кода приложения во время этой проверки изменён только `src/components/statistics-page.tsx`; значения и правила расчёта сохранены.

На большом наборе остаются долгие операции. Первое открытие с полным пересчётом: **127,3 → 119,0 с**; широкая группировка ЛНК: **30,6 → 31,1 с**, ПСТО: **21,0 → 22,1 с**. Это единичные большие прогоны, небольшие отклонения не доказывают устойчивую регрессию. Локальные результаты не гарантируют такие же времена на production.

Последующая [полная предкоммитная проверка пакета клейм](precommit-stamp-audit-2026-11-08.md) добавила исправления бизнес-логики и повторила влияющие пути на окончательной сборке: 26 действий при 200000 стыков, без ошибок JS и роста числа SQL; первое полное формирование 44,52 → 44,47 с на этом отдельном профиле. Его масштаб и состав отличаются от большого прогона выше.

Отдельно на каждой версии выполнены **46 открытий и 343 действия** при **250000 стыках, 750000 документах, 3600000 связях и 4100000 позициях**. Ошибок выполнения JavaScript в завершённых сравнениях не зарегистрировано.

## Результаты

Один `Intl.NumberFormat` теперь переиспользуется вместо создания экземпляра для каждой ячейки. На новой версии до/после исправления медиана работы JS при открытии вкладки сварщиков снизилась **91,93 → 32,96 мс**, при прокрутке — **107,10 → 79,39 мс**. На 200000 стыках: **171,17 → 101,03 мс**, SQL осталось 40. Это время работы JS, а не всей операции.

Ниже — медианы трёх повторений, прежняя версия → итоговая:

| Действие | Наблюдаемая готовность, мс | SQL |
| --- | ---: | ---: |
| Картина стыка | 80,66 → 85,33 | 22 → 22 |
| Редактор стыка | 281,28 → 268,57 | 26 → 26 |
| Поиск клейма | 84,50 → 64,46 | 0 → 0 |
| Вкладка «Сварщики» | 200,82 → 197,79 | 4 → 4 |
| Журнал, 250000 строк, новый контекст браузера | 1033 → 1009 | — |
| ЛНК / ПСТО, тот же масштаб | 1025 → 1028 / 1031 → 1019 | — |
| Документы / программа линий, тот же масштаб | 3646 → 3624 / 601 → 596 | — |

Быстрый ввод: 61 событие, p95 **13,1 мс**, максимум **16,9 мс**, без длинных задач. Отдельные серии ПСТО: по 40 жестов, медиана JS **82,09 → 82,30 мс**, без длинных задач; доля кадров дольше 33 мс **4,53% → 4,78%**, в пределах разброса контрольных серий. Это интервалы кадров, не физический FPS.

Полусекундные скачки некоторых коротких замеров оказались связаны с опросом готовности в Playwright. При опросе каждые 16 мс руководство: **398 → 385 мс**. Первый поиск в фильтре ПСТО: **276–303 → 319–333 мс**, повторный — **69–78 мс** на обеих версиях. Серверные трассы также не показывают добавочной задержки в полсекунды. Небольшие различия первых запросов сохранены в артефактах.

Пиковая RSS сервера: **2293 → 2381 MiB**, браузера: **1656 → 1671 MiB**; максимум соединений БД — 5 в обеих версиях. Разницу остаточной RSS отдельно перепроверили одинаковыми повторными группировками со сборкой мусора: в текущей версии живой JS-объём после повторов стабилен около **34 MiB**, RSS снижается до **286 MiB**. Дополнительного накопления в этом ограниченном опыте не обнаружено; диагностические замеры не включались в времена приёмочных прогонов.

Состав большого тестового набора совпадает. В новой версии ожидаемо исчезли 250000 СП-03: сохранённые пары заполнены, удалённые слои больше не требуют дозаполнения. Идентичности стыков, итоговые статусы и целостность индексов сохранены. Поэтому более быстрое первое формирование нельзя приписывать только технической оптимизации: объём диспетчерских задач изменился по согласованному правилу.
