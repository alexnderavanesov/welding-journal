## Диспетчер и печать

Снимок диспетчера сжимается последовательными порциями без потери полей, задач или действий. Новых запросов и фонового опроса нет. Браузер без поддержки получает прежний ответ; повреждённый ответ не заменяет сохранённые задачи пустым списком, повтор восстанавливает данные.

Полная печать объединяет только соседние пустые ячейки, сохраняя столбцы, текст, нули, пробелы и оформление. Постраничный предпросмотр прежний; после печати, отмены или ошибки временный документ освобождается. Регрессии сверяют значения, геометрию, цвета и повторное открытие.

Одна и та же предельная фикстура 10000 × 111, production-сборка и браузер:

| Показатель | До | После |
| --- | ---: | ---: |
| Снимок 5000 задач по HTTP | 11,917 МБ | 0,436 МБ |
| Физические ячейки полного печатного DOM | 1110000 | 250000 |
| Подготовка полной печати | 5,219 с | 3,143 с |
| Суммарный наблюдавшийся RSS браузера за сценарий | 4319 МиБ | 2929 МиБ |
| Предпросмотр 100 строк | 2,495 с | 2,525 с |
| Выгрузка Excel | 1,443 с | 1,422 с |

Проверены все логические столбцы печати и последняя строка печати/Excel. Открытие и повторное открытие — по **1 RPC / 14 SQL**; печать/Excel не перезагружают строки. Возврат фокуса — одна проверка версии, 415 байт / 4 SQL. Ответ строк остался 9,12 МБ, Excel — 61,2 МБ; файл не сравнивался поклеточно.

**Предельная печать остаётся ресурсоёмкой:** на слабом компьютере возможны задержки. Сумма RSS процессов не равна уникальной физической памяти. Физический принтер и PDF средствами ОС не проверялись; алгоритм Excel не изменён.

## Большая пересборка

Сопоставимые локальные прогоны одной фикстуры на Node 24.19.0: 200000 стыков, 100000 повторных циклов, четыре вида документов, 20 применений и 21 предпросмотр. Оба прогона использовали одинаковое диагностическое профилирование, без искусственной сборки мусора.

| Показатель | До | После |
| --- | ---: | ---: |
| Наблюдавшийся серверный RSS | 755 МиБ | 620 МиБ |
| Наблюдавшийся heap JavaScript | 463 МиБ | 332 МиБ |
| Первый предпросмотр | 23,325 с | 20,361 с |
| Применение с переходами между пакетами | 695,358 с | 656,851 с |
| SQL предпросмотра / применения | 107 / 4482 | 107 / 4442 |

RSS измерялся каждые 500 мс, не как точный пик ОС. Heap после завершения вернулся примерно к 20 МиБ в обоих прогонах. Прежний разброс 740–1060 МиБ из [аудита](precommit-audit-2026-10-09.md) не воспроизведён как утечка; его точная причина не установлена.

Устранено перечитывание неизменившихся первичных документов при переименовании повторного цикла. Действительно затронутые общие документы по-прежнему учитываются целиком. Регрессия четырёх видов падала до исправления. Компактное чтение фактов сверено с обычным SELECT на PostgreSQL, включая даты, числа, пустые значения и точную ревизию всех полей.

Итог обоих полных прогонов: 4000 → 8000 документов, все 800000 позиций и факты сохранены. Четыре прежних документа по 100000 позиций явно отклонены существующим ограничением и не изменены. Пределы пакетов и таймауты не увеличивались.

Та же пересборка прошла при **2 CPU / 2 ГиБ / без swap**, Node 22.23.2, штатный heap, без профилировщика: пик контейнера **454 МиБ**, без OOM, те же проверки фактов. PostgreSQL и браузер вне лимита приложения — это не испытание всей системы на машине с 2 ГиБ.

## Совместная работа пяти клиентов

Исходный смешанный сценарий 200000 стыков / 1000 линий / пять браузерных контекстов прошёл при тех же 2 CPU / 2 ГиБ и трёх минутах совместных действий. Пик контейнера — **445 МиБ**, без OOM и ошибок клиентов. Выполнены 26 сохранений и импорт 580 стыков; хеши 199599 незатронутых стыков совпали. Проверены документы, изменение допусков, отказ при ошибке и повтор операции.

Максимальный снимок задач: **5,24 → 0,210 МБ**. Холодное открытие осталось около **43,6 с** — полный расчёт не мгновенный. Рабочая часть дала 7908 SQL против прежних 7326, но выполнила больше действий: прежде было 23 сохранения / 540 импортированных стыков. Это не сравнение одинакового числа операций.

**6,5 секунды покоя — 0 RPC / 0 SQL приложения.** Серия focus/reconnect — ровно одна проверка версии на клиента: 417 байт, вместе 8 SQL.

Обычные окна отдельно под тем же лимитом: редактор 493–504 → 516–522 мс; программа линий 1344–1355 → 1352–1354 мс; детали 215–228 → 213–218 мс. Существенного замедления не выявлено, но эти замеры не доказывают отсутствие любой задержки. Ввод на 1200 кандидатах: p95 ЛНК 87,3 мс / ПСТО 111,9 мс; прежние 3 / 2 запроса строк.

## Границы изменений

Итоговые проверки: **4866 модульных тестов / 522 файла**, проверка типов, production-сборка с **134 RPC**, `git diff --check`; полный браузерный набор — **293 прошли / 4 специальных пропущены, 20,7 минуты**, без повторных попыток. Все четыре специальных сценария пройдены отдельно; большая пересборка дополнительно проверена под лимитом памяти. Проверены откат пакета при поздней ошибке, потеря ответа и повтор, конкурентные окна, конфликт имён, связанные послойные названия, ТК и реальное редактирование допусков. Расчёт после открытия на 200000 стыков сохранил **177 SQL**, прежний предел меньше 200 соблюдён.

Новых ошибок сервера/браузера нет. Предупреждения Nitro/manualChunks и NO_COLOR/FORCE_COLOR прежние. Печатные снимки до/после просмотрены; геометрия и оформление совпадают.

Схема БД, миграции, зависимости и production-конфигурация не менялись. Руководство пользователя не требует изменения: действия пользователя и правила остались прежними. Коммит, push, деплой и операции с production не выполнялись. Реальный production-бэкап по-прежнему отсутствует; эти тесты не заменяют проверку его восстановления или готовности production к выпуску.

Собственная тестовая БД и нагрузочные контейнеры удалены, порт 3100 свободен. Рабочая БД не использовалась для фикстур. Остановленный dev-сервер восстановлен с проверенной локальной `welding_tracker`; `GET http://127.0.0.1:3000/journal` вернул 200. HEAD остаётся `db3e60a1`, новые изменения не закоммичены.
