## Стоимость и ограничения

- Для 1000 записей истории измерение включает захват исходных полей: медиана без/с происхождением **270 → 283мс**, SQL **12 → 12**, JSON после первого прохода больше на **37 байт/запись**. Три чередующихся пары — локальная оценка, не гарантия нулевой стоимости.
- Все клиентские JS/CSS после исправлений аудита суммарно больше на **418 байт gzip**. Относительно C6 после оптимизации JS больше примерно на **8,24 КиБ gzip / 0,47%**. Это сумма файлов, не объём первоначальной загрузки. Серверных node:crypto, node:async_hooks, AsyncLocalStorage, адресов PostgreSQL и browser-external shim в проверенной публичной сборке не найдено.
- Одинаковые жесты при раскрытых группах, медиана P95 интервалов кадров C6 → текущая: Chrome вертикаль **29,1 → 29,3мс**, горизонталь **24,6 → 24,9мс**, resize **17,35 → 17,65мс**; WebKit **19 → 19 / 22 → 23 / 26 → 26мс**. По три повтора, для Chrome resize — два без профилирования. Запросов данных во время жестов нет. Исходные значения и максимумы сохранены в motion-final-comparison.json. Различия небольшие, но отдельные показатели выше; это не доказательство улучшения каждого кадра или статистической эквивалентности.
- Двадцать циклов / 510 действий через пять таблиц: после исправления конечный heap снизился **61,7–62,8 → 44,5–45,7MiB**, рост за последние десять циклов — **10,17–10,30 → 0,81–0,96MiB**. До исправления строки в цепочке замыканий накапливались **1800 → 11100**, после неё прежняя цепочка не обнаружена; общее число объектов строк уменьшилось **22316 → 21413**. Снимки диспетчера имеют постоянный размер; кэши и текущие данные сохраняются. В обоих сравниваемых прогонах **1301 RPC**, нет незавершённых запросов, по одной смонтированной таблице; объём ответов близкий, но не строго одинаковый: **65,400 → 65,412MB**. Остаточный рост не разложен точно без снимка после десятого цикла; между снимками после пятого и двадцатого циклов растут преимущественно код и сетевые метаданные браузера, а объекты данных уменьшаются. Это подтверждение устранения конкретного удержания, не всех возможных утечек.
- Сборка C6 сама показывала рост около 5,5–5,6MiB за последние десять циклов. Сохранённое раскрытие усилило существовавшую цепь, добавляя нужные чтения видимых дочерних строк при возврате и фильтрации. Эти дополнительные 114 RPC объяснены по действиям; исправление памяти не отменяет раскрытие, кэш или свежесть данных и не добавляет лимитов.
- В полном прогоне повторно проверены 200000 стыков: чтение ЛНК/ПСТО, цепочки, допуски и выбранные ID. Для контекста 1/500 стыков SQL постоянен: ЛНК 10/10, ПСТО 9/9. Для остальных изменённых масштабируемых путей — проверка сложности, пакетности и счётчиков запросов плюс ранее выполненные отдельные измерения. Это не новый нагрузочный прогон каждого opt-in профиля.

Первичное построение индекса диспетчера в сценарии допусков — **33,45с**, последующие изменения материала **0,27–0,53с**. Это разные операции; эти значения не доказывают регрессию и не означают время каждого обычного открытия отчёта.
