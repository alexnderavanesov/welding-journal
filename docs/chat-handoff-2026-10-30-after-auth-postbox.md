## Последние продуктовые решения

Основные источники: [полный план](authentication-and-access-plan-2026-10-29.md), [реализация](authentication-implementation-2026-10-30.md), [матрица операций](authentication-operation-matrix-2026-10-29.md), [интерфейс](authentication-interface-2026-10-30.md), [активность](user-activity-2026-10-30.md). Публичной регистрации и самостоятельного публичного восстановления нет. Восстановление инициирует администратор; для администратора — владелец. Защита владельца опирается на устойчивый ID. Восстановление владельца — отдельная операторская процедура, не запасной публичный вход.

Повторное приглашение той же почты создаёт нового пользователя, не наследующего прежнюю историю. ФИО в прошлых событиях — снимок на момент действия, переименование его не переписывает. Одновременные приглашения одного адреса защищены уникальностью и обработкой конфликта.

## Ограничения для продолжения

- **Без субагентов.** Делегирование возможно только после отдельного подтверждения пользователя с конкретной пользой. Модель и уровень рассуждения автоматически не менять.
- До нового поручения — только чтение/обсуждение. Никаких автоматических commit/push/deploy, production-миграций, изменения почты/DNS/Coolify, восстановления БД или отправки писем. Read-only production не разрешает тесты, нагрузку либо действия со скрытой записью состояния. Не восстанавливать прод старым дампом.
- Сохранить текущие checkout/main, незакоммиченные файлы, рабочие данные и процессы. Не создавать worktree, не переключать ветку, не выполнять reset/stash. Не запускать одновременно из двух чатов тесты с общей БД; не архивировать старый чат и не отправлять ему сообщения без поручения.
- Когда реализация отдельно разрешена, действует постоянное разрешение на **проверенные локальные миграции на main**, включая рабочую БД с сохранением данных: `src/db/schema.ts` → `pnpm db:generate` → просмотр → `pnpm db:migrate`. SQL вручную не писать. Это не команда мигрировать сейчас. Remote — только отдельное прямое разрешение и штатная `pnpm db:remote-migration`.
- Fixtures/автотесты/нагрузка — только отдельная проверенная пустая локальная БД и отдельные файлы/локальная доставка. Не использовать production или рабочую БД для синтетических записей. Репетиция реального дампа нужна для значимых изменений/миграций, не безусловно для каждого мелкого выпуска.
- При изменении поведения обновлять встроенное руководство. Сохранять серверные права, атомарность, проверку версий, историю и бизнес-правила. Не считать администраторские права разрешением обходить системные проверки.

Памятка пользователя сохранена в `docs/production-links.md`; HTML и редактируемый Excel также лежат в игнорируемом `outputs/`. Пароли, ключи и одноразовые ссылки в передачу не переносились. Документ передачи и прежняя памятка остаются незакоммиченными.
