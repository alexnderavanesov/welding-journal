Тестовая фикстура полностью инвалидирует индекс, поэтому это не замер обычного сохранения одного стыка.

## Поведение

- Чужое изменение, фокус окна и публикация расчётов больше не заменяют здоровую открытую таблицу. Появляется «Есть обновления» с кнопкой «Обновить таблицу». Нового постоянного опроса нет.
- Собственное сохранение и ручное обновление сохраняют выбор по ID, раскрытые группы и положение страницы. Изменение фильтра/сортировки открывает новую выборку. При изменении состава строк точный прежний якорь может исчезнуть: используется ближайшая доступная позиция.
- Редактор получает свежую карточку; меню/групповые действия — точный состав выбранных ID одним пакетным запросом. Повторное открытие контекстов ЛНК/ПСТО читает свежие строки. Удалённый участник выбора запрещает открытие операции с неполным составом.
- Существующие проверки версии, атомарности и бизнес-правил при записи сохранены. Дополнительного запроса проверки перед сохранением нет. При конфликте черновик остаётся в форме.
- Дозагрузка, копирование диапазона и итоги не смешивают версии: устаревшему позиционному запросу требуется явное обновление. Счётчики dispatcher и journal независимы и численно не сравниваются.
- Неверный HTTP-ответ получает понятное сообщение и диагностическую запись без содержимого данных. Потерянный ответ сохранения не вызывает автоматическую повторную запись. Ошибка загрузки отдельного окна остаётся внутри окна; полное обновление доступно явно. Начальное восстановление приложения сохранено.
- Руководство пользователя обновлено для журнала, ЛНК и ПСТО.

Проверка версии читает одну строку индекса по первичному ключу; новое открытие действий читает выбранные ID, без загрузки всего журнала или RPC на каждый стык. Это проверка структуры запросов и локальных сценариев, не новый системный нагрузочный аудит на 200000 стыков.

Точную причину production `Invariant failed` по видео установить нельзя. Воспроизведены и защищены соответствующие пути HTTP-ошибки и отказа загрузки JS; это не доказательство идентичности исходного сбоя. Поведение production после deployment пока не проверено.
