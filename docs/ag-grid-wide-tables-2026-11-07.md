# AG Grid, часть 3: широкие таблицы — 07.11.2026

**Адресная проверка завершена; подтверждённого улучшения плавности Chrome не получено. Прототип не принят.** Он уменьшал работу JavaScript при выводе служебных дат, но кадровые результаты остались неоднозначными, местами худшими. Код приложения восстановлен побайтно к началу этой части; результаты частей 1–2 и остальные прежние изменения сохранены. В репозитории остаются опциональный измеритель и этот отчёт. Коммита, выпуска, production-действий и миграции нет.

## Что проверено

Журнал, ЛНК и ПСТО с полным доступным набором столбцов: **118 / 110 / 65** соответственно. Плоские строки и три раскрытых уровня групп; вертикальное колесо, горизонтальное движение в обе стороны и изменение ширины закреплённой «Линии». Отдельно проверена дальняя область служебных дат: обе даты заполнены, первая ячейка действительно покидает виртуальные колонки и восстанавливается с правильным значением, смещение составляет ровно 1600 px туда и обратно. Стандартный личный вид скрывает эти даты, поэтому результат этого случая нельзя распространять на обычный вид.

Установленный Chrome **157.0.8103.38**, viewport 1600×1000, локальные production-сборки, обычный CPU без искусственного замедления, 12 логических CPU / 64 GiB. Одноразовая фикстура: 5000 стыков, 50 линий; общий набор также содержит 1000 клейм и 700 документов. Основная матрица — по три повтора каждого жеста. Для области дат выполнено сравнение **исходная → прототип → исходная → прототип**, по шесть наблюдений на вариант каждого сценария. CPU-профили и дополнительный парный контроль отделены от основных замеров. Это не проверка масштаба 200000 или сети production.

## Кандидат и причина отказа

Найдено повторное создание `Intl.DateTimeFormat` для каждой служебной даты. Прототип переиспользовал два форматировщика — с секундами и без — при прежних `ru-RU` / `Europe/Moscow`. Значения не кэшировались. Форматы, изменяемый объект `Date`, московская полночь, явные часовые смещения, пустые/некорректные значения, фильтры и экспорт прошли адресные проверки.

В области дат медиана затрат JavaScript на одинаковый вертикальный жест уменьшилась на **7,4–14,4%** во всех шести сочетаниях отчёта и группировки. Однако это не означает более плавные кадры:

| Метрика прототипа | Результат |
| --- | --- |
| JavaScript, плоские строки | Журнал 99 → 91 мс; ЛНК 102 → 88 мс; ПСТО 98 → 91 мс |
| JavaScript, раскрытые группы | Журнал 105 → 92 мс; ЛНК 95 → 87 мс; ПСТО 103 → 90 мс |
| p95 RAF, вертикаль плоского журнала и ЛНК с датами | В объединённых сериях 16,8 → 33,3 мс; доля интервалов >33 мс выросла в пяти из шести вертикальных сценариев |
| Горизонтальное движение и изменение ширины | Неоднозначные результаты, устойчивое общее улучшение не подтверждено |

RAF здесь — диагностические интервалы, не физический FPS. Причинная кадровая регрессия от переиспользования форматировщиков не доказана: есть разброс и зависимость от доставки ввода. Но для принятия изменения именно ради **плавности Chrome** одних меньших затрат JavaScript недостаточно. Поэтому прототип и его временные unit-дополнения удалены; patch сохранён в артефактах.

Дополнительный контроль чередовал обычное создание и переиспользование форматировщиков на одной странице исходной сборки. После прогрева число новых объектов за жест сократилось **84 → 0**, p95 обоих режимов — 16,8 мс. Медианы JavaScript 111 → 91 мс получены лишь в трёх проходах на режим с большим разбросом; это подтверждает механизм, но не заменяет результат готовых сборок.

В остальных горячих участках профиля преобладали собственные обработчики AG Grid: чтение позиции viewport и перерасчёт ширины/стилей при resize. Нового обоснованного лишнего прикладного цикла не найдено. Ранее отклонённые CSS contain, объединение pointer events и пропуск горизонтального flush повторно в приложение не включались. Один агент независимо проверял кандидатов, профили, регрессии и арифметику результатов по разрешению пользователя.

## Проверки и состояние

Прототип прошёл 79 unit-проверок, TypeScript, сборку с разрешением 187 RPC-ссылок, по 7 адресных функциональных сценариев Chrome и WebKit. Это не отменило ограничение кадровых результатов. В измеренных жестах новых RPC не было; несколько начальных значений общего SQL-счётчика могут включать отложенную телеметрию предшествующей загрузки групп, поэтому нулевой SQL для каждого жеста не заявляется.

После восстановления исходной сборки прошли **77 unit-проверок, 7 функциональных сценариев Chrome и 7 WebKit**, TypeScript приложения и нового измерителя. Окончательные результаты записаны в `unit-final.log`, `final-chrome.log`, `final-webkit.log`, `typecheck-final.log` и `typecheck-e2e-final.log`. WebKit использован для совместимости, без отдельной матрицы производительности установленного Safari. В тестах WebKit подменяется только транспорт clipboard; Chrome проверяет настоящий буфер обмена.

Фикстуры и миграции выполнялись только в принадлежащей runner одноразовой БД `127.0.0.1:5432/welding_tracker_e2e`, с отдельным временным хранилищем файлов. Штатная рабочая БД не использовалась для тестовых данных. Тестовые серверы и одноразовая база убраны; сервер разработки и исторический прототип не запускались.

Артефакты: `outputs/ag-grid-wide-tables-2026-11-07/`. Основные данные — `baseline-full-chrome`, `candidate-a-chrome`, `baseline-return-chrome`, `candidate-repeat-chrome`, `paired-control-chrome`, `pooled-comparison.json`; сохранены обе сборки, профили, хеши исходников и `rejected-formatter-reuse.patch`. Первый черновой проход остановился из-за ошибочного требования >90 столбцов к ПСТО; условие исправлено с учётом его собственного состава полей, полный исходный проход выполнен заново, черновик в сравнение не включён.
