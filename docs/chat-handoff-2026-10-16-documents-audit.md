## Следующий этап и ограничения

Пользователь выбрал последовательность: новый чат → полная предкоммитная проверка накопленных изменений → исправления → коммит по отдельной команде → дальнейшие переносы отчётов. Исторические команды на аудит/коммит уже относились к предыдущему этапу; передача не повторяет их. Последняя реализация выполнена без агентов по прямой просьбе пользователя; сохранять этот режим до нового указания. Пользователь обеспокоен расходом лимита: не запускать лишние параллельные проверки или повторные полные прогоны без причины, но не сокращать согласованный объём будущего аудита молча. Модель/настройки при создании чата не переопределять.

- Никаких новых реализаций, тестовых прогонов, аудита или миграций до новой прямой команды. Никаких автоматических commit, push, deploy, stash/reset, смены ветки/worktree, остановки серверов или архивации старого чата. Сохранить рабочие данные, незакоммиченные файлы и игнорируемый макет. Оба чата используют одну папку; исключить одновременные изменения и runner одной тестовой БД.
- Production, включая `welding-journal-test.yums.ru`, разрешён только для релевантного просмотра без изменения сохранённого состояния. Это не разрешение на удалённые тесты, fixtures, пересчёты, миграции, получение резервов или push с автодеплоем. Конкретные production-действия требуют отдельного прямого поручения.
- Fixtures/нагрузка — отдельная проверенная пустая локальная БД и изолированное хранилище шаблонов. Рабочая `welding_tracker` не тестовая. Перед следующим запуском заново проверить host, имя, изоляцию и владение; здесь БД не опрашивались.
- Постоянное разрешение на проверенные локальные миграции сохраняется, когда сама реализация отдельно разрешена: только main, сохранить данные, Drizzle schema → штатная генерация → просмотр → штатная миграция. Не писать migration SQL вручную. Это не разрешение на миграции при чтении handoff.
- **Репетиция восстановления настоящего production-резерва и установки обновления — отдельная локальная задача перед push, не часть предкоммитного аудита и не препятствие локальному коммиту.** Резерв/шаблоны нужны отдельно; получение их и выпуск не разрешены. Это последнее человеческое уточнение заменяет старые записи про «следующий аудит».
