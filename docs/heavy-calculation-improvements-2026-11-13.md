# Тяжёлые расчёты — продолжение 13.11.2026

**Последующая проверка:** по отдельному поручению три соседние вкладки проверены в независимых старых/новых процессах; постоянная прибавка времени не подтверждена. Реализован показ предыдущего результата статистики при обновлении тех же параметров. [Новые измерения, выбранный вариант и проверки](statistics-isolated-and-refresh-2026-11-13.md). Числа ниже сохраняют исходную серию этого этапа.

Этап завершён локально. Это отдельное поручение после [первого этапа ускорений](performance-improvements-2026-11-13.md): улучшить оставшиеся тяжёлые расчёты, сохранив поведение и не добавляя сложность ради малой пользы в редких случаях. Коммит, push и production-действия не выполнялись.

Основной результат: сокращены лишние копии данных в диспетчере и повторные вычисления статистики. Прямое ускорение холодной группировки ПСТО не подтверждено. Дополнительный постоянный кэш по линиям не добавлен.

## Что изменено

- Процентные задачи диспетчера сохраняют нужный контекст стыка, оба процента контроля, цели и действия. Полная карточка с историей больше не дублируется в каждой такой задаче. Редактор по-прежнему получает актуальную полную запись по ID; исходная история сохраняется.
- Одинаковая принадлежность «линия → код → все её стыки» строится один раз для индекса кодов. Отдельные задачи остаются; индивидуальное предупреждение СП-08 не объединяется.
- Статистика повторно использует вычисленные признаки одной строки только внутри одного синхронного расчёта. Следующий расчёт читает свежие факты.

Изменены три файла приложения, итоговый прирост — 47 строк. Диагностика и регрессии находятся отдельно в тестовом коде. Новых таблиц, миграций, очередей и ограничений нет. Правила и пользовательские действия не меняются, поэтому руководство и версия расчёта не изменяются. Старые полные страницы задач совместимы; компактные появляются при очередном обычном пересчёте, без принудительного массового обновления.

Это длительность HTTP-запросов с расчётами, а не время полной отрисовки страницы или FPS. «Первый» означает отсутствие готового результата, не холодный дисковый кэш ОС. Основной выигрыш подтверждён серией A–B–B–A; затем временные факты статистики упрощены до одной записи на объект строки и окончательная сборка проверена дважды. В дополнительном финальном повторе SQL учитывался, семплирование памяти не включалось; память сравнивается по основному парному прогону. Диагностические CPU-профили не включены в сравнение скорости. Хост: M2 Max, 12 CPU / 64 ГиБ; PostgreSQL 18.4 в Docker, 12 CPU / 8,32 ГиБ, shared memory 1 ГиБ. Отдельного ограничения ресурсов приложения в этом этапе нет; числа не являются гарантией для production.

Во всех 34 ответах совпали бизнес-данные, порядок, состав и итоги; исключены только технические версии/временные метки. Дополнительно совпали все сохранённые статусы и коды, 494948 задач и 4952 страницы. Сократился объём представления задач, а не их количество. На отдельной фикстуре 250000 стыков частичный пересчёт двух линий суммарно из 26000 стыков полностью совпал с полным, включая содержимое всех сохранённых страниц.

## Оставшиеся ограничения

Холодные группы ПСТО: до 8,9–9,4 с, после 8,9–9,6 с; ускорение не подтверждено, первоначальный рост в финальном повторе не воспроизвёлся. В профиле около 4,7 с приходится на суммарное время SQL с передачей/декодированием, около 0,76 с — на классификацию ПСТО/ТВМТ; остальное связано с подготовкой и общей сводкой физических цепочек. Постоянные агрегаты по линиям потребовали бы отдельного учёта произвольных фильтров, перемещений, неполных цепочек и настроек. Дублировать правила или хранить полные карточки между запросами ради небольшого выигрыша нецелесообразно.

Остальные тяжёлые вкладки не ускорены: опоры 2,67–2,72 → 2,70–2,75 с, сварщики 5,66–5,81 → 5,80–6,01 с, линии 7,15–7,21 → 7,38–7,44 с. Небольшой рост в части измерений сохраняется; причинность по этим сериям не установлена. Их расчётные функции не изменялись. Это ограничение измеренного результата, а не доказательство ускорения всей системы. Реестры документов остались примерно на уровне 2 с / 3,1 с для страницы / групп.

Полное первичное сохранение статусов 250000 строк остаётся тяжёлым — около 22 с. Существующие пакетная запись, проверка актуальности и атомарная публикация сохранены. Отдельное хранилище статусов ради редкого первого заполнения не вводится.

Частичный пересчёт уже работает: шесть реальных сохранений на 50000 стыках, линии 6000/20000. Медианы 1,395/3,150 с → 1,374/3,215 с; существенного изменения нет, итоговые статусы/коды совпали. Этот замер выполнен на первом кандидате; окончательное изменение после него касается только внутреннего расчёта статистики. Новый кэш частичных расчётов не обоснован.
