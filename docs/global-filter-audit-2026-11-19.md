# Фильтры и сортировка — 19.11.2026

Полная проверка всего пакета завершена; последующие исправления, измерения и ограничения — в [предкоммитном отчёте](precommit-audit-2026-11-19.md). Ниже сохранены подробности отдельных этапов.

## Подтверждённая причина

В программе линий сервер уже возвращал полную сводку, но перед передачей в AG Grid клиент отрезал 30 строк. Фильтры заголовков, их списки значений и сортировка видели только эту страницу. Верхний жёлтый показатель фильтровал полный список **до** разбиения на страницы — поэтому его нажатие меняло доступные значения в заголовках. Это воспроизводит симптом пользователя; доступа к проду для проверки не требовалось.

Регрессия: 65 линий, единственная потребность в контроле находится у последней. На прежней сборке в фильтре «К назначению» отсутствует `1`, хотя общий расчёт его содержит (`outputs/global-filter-audit-2026-11-19/before.log`).

## Изменения

- Полный существующий результат передаётся в таблицу. Без группировки штатная пагинация AG Grid применяется после фильтров и сортировки; размер страницы остаётся 30. Новых серверных запросов или расчётов на изменение заголовка не добавлено.
- Сводка для просмотра/Excel получает все строки текущего отбора заголовков, а не только видимую страницу.
- Ненастроенная линия с отсутствующим расчётом больше не попадает в числовое значение `0`: её пустые показатели соответствуют пустым значениям фильтра.
- Пока полный результат рассчитывается, первые линии можно открывать. Окно фильтра показывает ожидание полного расчёта вместо частичных значений; сброс фильтра доступен. Выбранный порядок сортировки применяется и к поступившему полному результату; открытый фильтр получает полные значения без повторного открытия.
- Явный переход к линии из общего расчёта открывает нужную страницу; сохранены раскрытие групп, восстановление совместимых фильтров и приоритет ручного сброса при загрузке.
- При группировке используется существующая виртуализация с общей прокруткой страницы: группы и вложенные детали остаются целыми, а DOM ограничивается видимой областью. После снятия группировки возвращается первая страница по 30 линий. Руководство обновлено.

## Область проверки аналогичного дефекта

Проверялась последовательность **полный источник → отбор/сортировка → страница/виртуализация**, включая загрузку вариантов фильтра. Это проверка границ выборки, а не повторная проверка всех бизнес-формул каждого столбца.

| Область | Проверенный механизм |
| --- | --- |
| Журнал сварки, ЛНК, ПСТО | Общий `journal-grid`: условие и порядок применяются в SQL до `limit/offset`; варианты фильтров загружаются отдельно по полной области. Виртуальные поля без поддерживаемой сортировки не предлагают локальную сортировку страницы. |
| Реестры документов | `document-history-grid`: фильтрованный источник общий для количества, групп, страниц, выбора и вывода; сортировка предшествует ограничению блока. |
| Программа линий | Подтверждённый дефект исправлен для общего реестра и всех его вкладок. |
| Клейма, стыки и назначения внутри линии | В таблицу передаётся полный выбранный состав линии/клейма. Виртуализация ограничивает DOM, а не исходный набор. Изменённые назначения обновляют значения для фильтров и сортировки. |
| Программа ПСТО и исключения | `psto-line-assignment-summary` / `psto-exception-table`: SQL-фильтры до пагинации; варианты по полной области с исключением собственного условия. |
| Реестр схем и список стыков схемы | Метаданные фильтруются в SQL; расчётные показатели — до среза страницы. Поиск стыков выполняется по полному составу схемы. |
| Статистика: сварщики, линии, опоры | Полный результат соответствующего расчёта передаётся в таблицу; клиентские фильтры работают до виртуализации. Серверные параметры входят в ключ запроса. |
| Пользователи, справочники и правила | Полный доступный список либо серверный поиск до курсора; локальные таблицы не получают заранее отрезанный блок для самостоятельной фильтрации. |
| История действий и согласованные предупреждения | Условия и разрешённая область применяются на сервере до страницы. История не предлагает локальную сортировку загруженных событий. |
| Диспетчер | Поиск проверяет полный актуальный индекс задач; смещение применяется после совпадения. |
| Окна заявок, результатов, повторов, ТВМТ, до ТО; операции с документами | Клиентские отборы предшествуют `usePagePagination`/срезу. В серверных режимах поисковые параметры передаются в запрос, а локальные счётчики подписаны как число позиций страницы. |
| Предпросмотр импорта | Ограничение предпросмотра явно задано пользователем; локальная сортировка/фильтрация страницы не выдаётся за отбор полного импорта. |

В перечисленных остальных механизмах аналогичная обрезка перед самостоятельной фильтрацией не найдена. Проверка конкретных комбинаций и ограничения измерений приведены ниже.

## Уточнение предкоммитной проверки

Выявлен риск первоначальной реализации: штатная пагинация считала группы верхнего уровня, поэтому одна раскрытая группа с тысячей одинаковых значений могла одновременно отрисовать все линии в режиме `autoHeight`. Это устраняется использованием существующего ограниченного viewport с общей прокруткой страницы только при группировке. Панель групп учтена в геометрии прокрутки; явный переход раскрывает родителей и выводит нужную строку в viewport. Правила расчёта, серверные запросы и состав фильтров не меняются.

Добавлена регрессия на 1001 линию (1000 в одной группе): ограничение DOM, доступ к дальней строке, вложенные клейма/стыки, полный отбор и сортировка, возврат пагинации после снятия группы. Её браузерная проверка и проверка соседних сценариев входят в текущий предкоммитный прогон; результаты ниже относятся к предыдущему этапу и не доказывают корректность нового режима.

При расширенной проверке воспроизведён возврат страницы вниз после ухода от раскрытого клейма с оставшимся на его кнопке фокусом; настоящий wheel также затрагивался. Первоначальная гипотеза о недостаточном ожидании теста не объясняла повтор после окончания анимации. В общем упорядочивании DOM сохранённое поддерево с фокусом больше не перемещается: соседние строки переставляются вокруг него. Фокус, текстовое выделение и окончательный порядок сохраняются; таймеры и эвристики прокрутки не добавлены. Причина зависит от фазы браузерного layout, поэтому единичный успешный повтор исходной версии не считался опровержением.

На `candidate-v5-output` исходный расширенный сценарий прошёл **3 раза в Chrome**: 1001 линия, ограниченный DOM, вложенные детали, полный отбор/сортировка, пагинация, программный возврат, настоящий wheel и Home, сохранение фокуса и устойчивая позиция после завершения кадров. Новый unit сначала падал на перемещении поддерева с фокусом; после исправления DOM-order/reveal — **11 тестов passed**. Локальная production-сборка прошла. Это целевая проверка исправления, не замена полного итогового набора. Артефакты: `outputs/precommit-2026-11-19/grouped-scroll-diagnostic-v4*`, `grouped-scroll-v5.log`, `grouped-scroll-v5-results/`, `build-v5.log`. Диагностические wrappers не входят в приложение или постоянные E2E-тесты.
