Аудит, реализацию и миграции сейчас не запускать.**

## Последние решения и следующий этап

- Пользователь доволен внедрением AG Grid в сварочный журнал. Перед переносом других отчётов выбран полный предкоммитный аудит всех накопленных изменений, исправления и затем коммит по отдельной команде. Проверять весь diff, а не только последнюю кнопку или библиотеку. Запуск аудита в новом чате ожидает отдельного «Проведи полную предкоммитную проверку»; передача его не запускает.
- Новый ключ лицензии ожидается. **Ожидание ключа не блокирует локальный аудит и коммит.** Это последнее уточнение заменяет прежнюю обязательную последовательность «сначала подключить ключ → затем новый чат». Пуш, особенно запускающий автодеплой, и деплой не разрешены.
- Затем ЛНК и ПСТО — отдельные будущие этапы по новой команде, с переносом всего актуального согласованного поведения журнала, включая мелкие исправления. Документы оценивать отдельно: реестр, формирование, история и предпросмотр имеют разные задачи. Сейчас миграции этих экранов не начинать.
- Рабочий диспетчер оставить как есть. Макет программы линий **поставлен пользователем на паузу, не отменён**; пользователь намерен вернуться с существенной переработкой, но её содержание ещё не сформулировано. Старое согласование перестройки диспетчера не возобновляет работу.

## Ограничения

- Сохранить рабочие данные, все незакоммиченные и игнорируемые макеты/резервные копии. Без автоматических commit, push, deploy, stash/reset, смены ветки, нового worktree, остановки серверов или архивации прежнего чата. Не посылать другим чатам команды без отдельного разрешения. Общая папка: исключить одновременные правки и конкурирующие runner одной тестовой БД.
- Production (`welding-journal-test.yums.ru`, несмотря на название) — только релевантный просмотр без изменения сохранённого состояния. Пользователь пояснил, что использует его для тестирования, а не продажи; **это не отменяет ограничения AGENTS.md и не разрешает удалённые тесты, fixtures, пересчёты, миграции, инфраструктурные изменения или push с автодеплоем**. Любое конкретное изменение production требует отдельного прямого поручения.
- Автотесты/fixtures/нагрузка — только отдельная проверенная пустая локальная БД и отдельное временное хранилище шаблонов. Рабочая `welding_tracker` не тестовая. Перед будущим запуском проверить изоляцию и владение; старое отсутствие тестовой БД не считать текущей проверкой.
- Постоянное разрешение на локальные миграции сохраняется, когда реализация отдельно поручена: только `main`, проверить локальный host и точное имя БД, сохранить данные, schema Drizzle → штатная генерация → просмотр → `pnpm db:migrate`. Не спрашивать повторно разрешение на уже согласованный локальный шаг. Не писать migration SQL вручную; remote требует отдельного разрешения. Само чтение контекста миграций не разрешает.
- Новые функции/правила/настройки сопровождать встроенным руководством. Не переносить системные поля в редактор стыка; сохранять серверную валидацию, конечную запись при частичных импортах, все одновременно обнаружимые ошибки, транзакции и защиту конкуренции. Правила диспетчера и версия расчёта — по AGENTS.md.

Системный аудит дополнительно расширяет смешанные сценарии, память/длительные сессии/ресурсные пределы. Старые прогоны, пользовательские spot-check и совпадение кода/тестов/руководства не являются независимым доказательством правил. Непроверенный реальный резерв честно оставить отдельным ограничением.

Важные действующие бизнес-уточнения предыдущего этапа: **четыре единообразных сценария ПСТО** (назначение/возобновление и вход на назначенную линию — основной НК → до ТО; отмена и выход на неназначенную — обратно), исходно KEEP, по стыку, весь комплект включая заявки без результата, пустой целевой этап/реквизиты/хронология/зависимости. История соседа не заменяет собственную. Специалисты сохраняются снимком; конфликт подписей при объединении после подтверждения очищает обе роли только конфликтующего итогового документа. Отдельного произвольного переноса этапа нет. Результаты требуют названия/даты, исторические пробелы не заполнять выдуманными фактами. ЛНК замены/удаления применяются атомарно при сохранении с общей сводкой. Неофициальному допустимо довнести «годен» другого метода при сохранённом браке, но нельзя исправить сам брак на годный. Защиту предшественника/основания катушки не снимать; старые сохранённые связи не переписывать автоматически.
