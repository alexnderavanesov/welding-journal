## Проверки

Просмотрен весь diff и новые файлы относительно `main`, `3bac76fa16f8e03a760e2b0e93c34be34d41c485`; сверены актуальные требования журнала, план программы линий и исключения. Проверены полные группы/выбор/диапазоны, физические итоги, версии/кэши, отмена/ошибки/повтор, RPC/SQL, виртуализация, клавиатура/фокус, меню, редактирование, импорт, документы/экспорт и смежные отчёты. Полный E2E включает удаление/восстановление цепочек и документов, официальность, ПСТО, допуски и stale/concurrent-сценарии.

- Итоговый код: **624 файла / 6325 unit-тестов прошли**, 2 опциональных пропущены; typecheck приложения/E2E и production build успешны, все 158 RPC согласованы с manifest. Аудиты зависимостей — с указанным исключением. `git diff --check` чистый.
- Полный Chrome E2E: **645 прошли, 23 опциональных пропущены**, один сбой ожидания фокуса разобран и исправлен. После исправлений — **57 проверок журнала**, 8 опциональных пропущены. Последняя узкая правка отказа буфера повторно проверена профильными тестами, полным unit-набором, typecheck/build и браузерным копированием; остальные сценарии полного E2E ею не затронуты.
- **WebKit 26.5: 38 прошли**, 7 опциональных пропущены. Дополнительно по **3 клавиатурных повтора** Chrome/WebKit. Native clipboard/CDP проверены в Chrome; отложенный ClipboardItem также покрыт unit-тестами. Отмена серверного запроса на подготовленной одноразовой БД: два случая, статус 499. Запуск без готовой БД возвращал ожидаемый для readiness статус 503; предпосылка уточнена в скрипте.
- **200000 стыков:** точные итоги 400000 ячеек, копирование 200000 × 2, группы, фильтры/экспорт, устаревшие версии, ограниченность DOM/SQL. Два исходных API-прогона: 565 SQL, 24 строки DOM у конца таблицы, копирование около 1,64–1,66 с. При 40 раскрытых группах после очистки осталось 1900 карточек, возврат сохраняет раскрытие и выбор; RPC подсчёта выбора — 0. Мягкий бюджет может временно превышаться в промежуточных кадрах.

В двух исходных последовательных нагрузочных прогонах дальняя группа не загрузилась из-за PostgreSQL `could not resize shared memory segment ... No space left on device`. Локальный Docker тогда имел **67108864 байта `/dev/shm`**. Одиночный прогон бюджета прошёл; исходная последовательность повторно воспроизвела ошибку. Контрольная последовательность **7/7** прошла с `PGOPTIONS='-c enable_parallel_hash=off'` только у тестовых процессов; SQL осталось 565. На том этапе постоянные настройки и контейнер не менялись. Диагностика RPC/сети теперь сохраняется и при падении теста.

**Последующая настройка по разрешению пользователя:** в локальном `docker-compose.yml` установлен `shm_size: "1gb"` (1073741824 байта). Контейнер пересоздан с прежним образом и постоянным томом; идентификатор кластера, список БД с OID и количество рабочих стыков до/после совпали. Та же последовательность копирования, API и бюджета на **200000 стыков прошла 7/7 за 4,4 минуты**, без `PGOPTIONS`, с `enable_parallel_hash=on`. SQL — 565; после 40 раскрытых групп осталось 1900 карточек, возврат сохранил раскрытие; подсчёт выбора — 0 RPC. Ошибок PostgreSQL, HTTP/RPC и страницы нет; зафиксирована одна штатная отмена запроса при смене состояния. Одноразовая БД удалена, локальный журнал отвечает 200. Подробности с SHA-256: `../welding-journal-local-measurements/2026-10-22-shm-1gb/`. Это подтверждение конкретного нагрузочного сценария, не общего многопользовательского запаса памяти и не ускорения отрисовки. Перед большим аудитом ресурсы по-прежнему фиксируются явно.

Свежий контроль движения: production build, обычный CPU, DPR 2, 111 столбцов, три раскрытых уровня. Прокрутка — по одному быстрому проходу в каждом направлении, resize — три повтора:

## Сохраняющиеся ограничения

После этой проверки выполнена отдельно разрешённая [оптимизация подготовки фильтра](journal-filter-cache-2026-10-22.md): SQL поиска 7 → 5, сохранены проверки актуальности. Полный unit-набор и профильные E2E повторены для этой правки; результаты большого Chrome E2E выше относятся к предшествовавшему проходу.

- Поиск в фильтре с 200 000 уникальных значений сохраняет согласованный пользователем 22.10 компромисс: прежние замеры открытия 2,06 → 1,45 с, поиска 33 → 166 мс. Эти исторические цифры не являются свежим замером текущей проверки; текущий гибридный вариант принят, этап оптимизации закрыт.

- Восемь специализированных нагрузочных профилей, широкий вывод 200 000 × 111 и полный многопользовательский системный аудит не входят в эту проверку. Репетиция обновления реальной резервной копии остаётся отдельной локальной задачей перед push.
