## Нерушимые ограничения

- **Без агентов.** Экономия токенов важнее ускорения; делегирование — только после отдельного согласования конкретной пользы.
- Без новой прямой команды не реализовывать, не запускать аудит/тесты, не коммитить, не делать push/деплой, не менять ветку и не создавать worktree. Не stash/reset и не переписывать чужие изменения или рабочие данные.
- Production — среда с работающими пользователями; использовать обычное слово «production/прод». Завершённые разрешения на этот выпуск не являются постоянными. Любые изменения кода, данных, схемы, документов, Coolify, сервера, инфраструктуры и настроек требуют **прямого разрешения конкретного действия**. В том числе push в ветку с autodeploy. На первом ходе нового чата к production не обращаться.
- AGENTS разрешает относящийся к новой задаче безопасный просмотр production, но не тесты, нагрузку, сохранение или команды обслуживания. Если просмотр может менять сохранённое состояние, сначала исследовать локальный код.
- Постоянное исключение: при отдельно разрешённой реализации локальные миграции разрешены без повторного вопроса, включая рабочую локальную БД. Сначала проверить локальный хост, точное имя базы и сгенерированную миграцию, сохранить данные; миграции только с main. Fixtures/нагрузка/разрушительные тесты — только в отдельной проверенной пустой локальной тестовой БД. Это не разрешение мигрировать при передаче контекста.
- SQL миграций вручную не писать: `src/db/schema.ts` → `pnpm db:generate` → просмотр → штатная команда. Remote — исключительно отдельно разрешённая полная `pnpm db:remote-migration`, не прямой Drizzle против удалённой БД.
- Изменения пользовательского поведения сопровождать обновлением `src/components/user-guide-page.tsx`. Не ослаблять проверки, историю, атомарность, конкурентные защиты и существующие predecessor/coil-ограничения.

Сохранять серверные фильтры/сортировку/страницы всей выборки; клиентская группировка загруженного набора не глобальная. Групповые количества — физические соединения, а не все записи ремонтов. Системные поля — только dedicated workflows, не обычная форма стыка. Импорт/массовая замена проверяют итог после объединения со старой записью и показывают все совместно обнаружимые ошибки. Новые правила диспетчера требуют версии расчёта и покрытия формы/сервера/persisted/virtual индекса.
