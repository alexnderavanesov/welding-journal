- Production — среда реальных пользователей. Изменение кода, данных, схемы, документов, настроек, Coolify, сервера, контейнеров, хранилища и push с autodeploy требуют прямого разрешения конкретного действия. Read-only просмотр по AGENTS не разрешает тесты/нагрузку/скрытые записи. На первом ходе нового чата production не открывать.
- При отдельно разрешённой реализации действует постоянное разрешение на **проверенные локальные миграции**, включая рабочую БД, без повторного вопроса: main, точный локальный адрес/имя, сохранность данных, Drizzle schema → generate → просмотр → штатный migrate. SQL миграций вручную не писать. Remote migration — только после отдельного разрешения, через `pnpm db:remote-migration`, не прямой Drizzle и не случайный старый remote env.
- Fixtures/нагрузка/автоматические разрушающие проверки — только отдельная проверенная пустая локальная БД и временное хранилище. Штатный E2E использует **127.0.0.1:5432/welding_tracker_e2e**, проверяет отсутствие до создания и удаляет только собственную базу. Рабочую `welding_tracker` не очищать и не засевать.
- Сохранить предметные правила, права, историю, физические итоги, полные результаты, атомарность и конкурентные защиты. Новое поведение сопровождать встроенным руководством. Последние человеческие решения важнее промежуточных планов.
