## Обязательные ограничения

- **Без субагентов**: экономия токенов важнее ускорения. Не менять модель/настройки нового чата. Делегирование требует отдельного согласования конкретной пользы.
- Сейчас только чтение контекста и ожидание. Без новой команды — никаких реализаций, тестов/аудитов, миграций, commit/push/deploy; не менять ветку, не создавать worktree, не stash/reset и не останавливать серверы. Два чата используют одну папку: исключить параллельные правки и runner с общей disposable-БД.
- **Production — среда реальных пользователей**, несмотря на историческое `test` в домене. Не менять данные, код, настройки, Coolify, инфраструктуру, контейнеры, документы и связанные службы без прямого разрешения конкретного действия. Push с автодеплоем тоже требует отдельного разрешения по AGENTS. Разрешения на уже завершённый выпуск не переносятся на следующий.
- Read-only production не разрешает нагрузку, тесты или скрытые записи. В том числе открытие приложения может инициировать серверный пересчёт; сначала проверять код. Для знакомства с контекстом production не нужен.
- При отдельно разрешённой реализации действует **постоянное разрешение на проверенные локальные миграции**, включая основную локальную БД: только main, точный локальный адрес/имя, просмотр сгенерированной миграции, сохранность данных. Schema → `pnpm db:generate` → проверка → штатный migrate; SQL миграций вручную не писать. Это не разрешение миграции сейчас. Remote требует отдельного разрешения и штатного `pnpm db:remote-migration`.
- Fixtures/автоматические проверки/нагрузка — отдельная **пустая локальная** БД и временное хранилище; рабочая `welding_tracker` не тестовая. Штатный `e2e/run.ts` проверяет точную `welding_tracker_e2e`, отказывается заменять существующую и удаляет только собственную. Секреты, лицензию и приватные настройки в сообщения/логи не копировать.
- **Последнее решение о репетиции обновления:** для этого выпуска пользователь её отменил. В будущем проводить при крупных изменениях, миграциях, существенных системных переделках и сходных сложных обновлениях, а не перед каждым push. Старые безусловные требования в отчётах заменены этим решением. Репетиция — отдельная локальная задача, не повод получать новый production-бэкап автоматически.
