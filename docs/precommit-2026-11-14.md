## Найдено и исправлено

**Потеря места в реестре документов при возврате на вкладку.** WebKit иногда возвращал к заголовку далёкой группы вместо прежнего документа, если дочерний блок загружался с задержкой. Сохранение позиции выполнялось в пассивной очистке React, когда таблица уже удалена. Оно перенесено в очистку перед удалением DOM; новые запросы, кэши или таймеры не добавлены. Новый unit-тест воспроизвёл дефект до исправления и прошёл после него. Весь документный профиль прошёл в Chrome (28 проверок) и WebKit (28); проблемный сценарий дополнительно прошёл три раза. Руководство дополнено описанием возврата к прежней строке.

Исправлены ошибки измерительных тестов без ослабления требований:

- Проверка прав иногда считала две штатные SQL-проверки готовности выпуска после истечения пятисекундного кэша лишними запросами идентификации. Красный прогон подтвердил точную причину. Теперь отдельно учитываются только две конкретные формы служебного SQL; тест намеренно пересекает срок кэша, строгая проверка остальных запросов и запреты доступа сохранены. Весь файл — 14/14.
- Тест 600000 документов читал старые строки перед подгрузкой нового блока. Теперь прокручивается реальный владелец прокрутки — страница — и одновременно проверяется готовность целевого блока. Конец реестра требует точного последнего индекса; таймаут не увеличен. Полный повтор профиля прошёл.
- Замер раскрытия групп включал незавершённую предыдущую группировку и ступенчатое ожидание локатора Playwright. Теперь настройка и раскрытие измеряются отдельно, готовность настройки проверяется по кадрам. Подтверждение — трассы и три отдельных повтора на каждой сборке; функции приложения для этого не менялись.

**Отдельная диагностика WebKit при уходе со страницы.** В двух прогонах проверка отсутствия `pageerror` остановила сценарий удаления официального тёзки, хотя проверки фактов, восстановления, продолжения цепочки и защит прошли. Сообщение `Fetch API cannot load … due to access control checks` возникало во время reload/goto для чтения старой таблицы. На минимальной локальной странице без приложения WebKit выдал его 10/10 раз при `fetch` в `pagehide`, несмотря на `try/catch`, без событий `error`/`unhandledrejection`. Playwright преобразует этот нативный console-сигнал в `pageerror`. Исходные отказы сохранены; исключение ошибок из тестов не добавлялось. Это ограничение диагностики браузера, а не подтверждённая ошибка удаления или прав. Полностью зелёным исходный WebKit-прогон не объявляется.
