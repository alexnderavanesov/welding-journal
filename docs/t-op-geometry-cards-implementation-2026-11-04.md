# Т-03 и Т-05 — допуски и технологические карты

**Уточнение 05.11.2026:** ниже сохранён исторический отчёт первоначального этапа 04.11. Последующее решение запрещает разнородное Т и комбинированную сварку: одна группа материалов, один способ, D1/T1 и одно официальное клеймо. Упоминания положительных проверок двух групп/нескольких способов ниже описывают прежний этап и не задают действующие правила. Актуальные требования — в [итоговом плане](t-op-implementation-plan-2026-11-03.md), последующая проверка — в [журнале реализации](t-op-implementation-progress-2026-11-04.md). Исторические результаты прогонов сохранены.

Локальная реализация и проверка участка Т-03/Т-05 завершены 04.11.2026 в составе [полного плана Т-01…Т-22](t-op-implementation-plan-2026-11-03.md). Финальные профили: Chrome **33/33**, WebKit **60/60**; все 11 сценариев `t-op-weld-core.spec.ts` прошли в обоих браузерах, отдельный набор ТК — 9 сценариев в WebKit. Синтетические данные использовались только в изолированной локальной БД. Общий результат всей задачи отражён в [журнале реализации](t-op-implementation-progress-2026-11-04.md).

**Проверено:** целевой прогон 16 файлов / 383 теста прошёл. Лог: `outputs/t-op-geometry-cards-2026-11-04/unit.log`. Включены `support-qualification`, `support-technology-cards`, dissimilar/выбор клейм/диспетчер, существующие ТК-модули, mocked серверные операции и компонентные сценарии редактора/поля/массового подбора. В этой серии существующий общий путь пакетной записи проверен на 200000 записей; для Т отдельно подтверждены тот же единичный matcher/usage вызов и отсутствие новых запросов в цикле. Это не нагрузка PostgreSQL или браузера.

Первое расширение серии выявило ошибку ожидания нового компонентного теста: редактор передаёт строковый draft, числа нормализуются сервером. Ожидание приведено к действующему контракту, затем вся серия повторена успешно. Бизнес-ожидания по Т заменены по согласованному плану; старые проверки неизвестного типа продолжают использовать действительно неизвестный код вместо теперь разрешённого Т.

Общая проверка типов и финальные интеграционные запуски прошли. На изолированной БД в Chrome и WebKit подтверждены первый ввод даты/автоТК, сохранение применимой архивной карты, проверка обеих групп материалов и всех способов, несвязанная правка после утраты допуска и отказ изменения входов допуска. В раннем прогоне ошибочный тестовый номер `ОП-GROUP` отвергался проверкой служебной R раньше проверки допуска; fixture заменён на `ОП-MAT`, ожидание СП-02 сохранено и успешно проверено повторно.

**Остаётся:** согласованная локальная репетиция на свежей выгрузке после предоставления её пользователем перед коммитом. Прод не изменялся; коммит не создавался.
