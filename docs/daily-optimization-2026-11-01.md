### Что изменено

- Списки значений всех серверных отчётов используют один русский числовой `Intl.Collator`; порядок, пустые варианты и количества сохранены. Для обычного фрагмента итогового статуса, уже входящего в «не годен по дублю» (например, «годен»), отбор больше не вычисляет суффикс методов дублей. Поиск самих методов, точные значения и специальные символы сохраняют прежний путь.
- Для первых страниц явных сортировок проекта, шифра, линии ↓, даты и статуса сначала выбираются ID по полному прежнему порядку, затем читаются карточки. Линия ↑, глубокие страницы и выбор по ID сохраняют прежнее чтение. Линия ↑ исключена после замеров без выигрыша; все порядки по умолчанию также сохранены. У порядка по умолчанию сварочного журнала нет ID среди ключей разрешения совпадений, поэтому двухфазный LIMIT мог переставить полностью равные строки. Старое ускорение естественного порядка стыков сохранено.
- В едином полном расчёте групп повторно используется нормализация одинаковых сочетаний проекта, шифра и линии, включая перемешанные строки. Небольшой локальный кэш отключается при высокой кардинальности и не хранится между вызовами; длинные значения обрабатываются напрямую. Расчёт физических цепочек, WDI, дат, статусов и истории прежний.
- В назначениях программы обновляются изменённые строки и фильтры затронутых методов. Контексты выбора, идентичности и редактирования разделены; общие подсказки линии, зависимости ПВК, актуальные проверки и состояние сохранения продолжают обновляться.
- Выбранные системные документы и их связи читаются совместно: 7→3 SQL для одного типа, 10→3 для смешанного выбора. Версии, специалисты, старые метаданные, точные позиции циклов и независимые перечитывания после блокировки сохранены.
- Предпросмотр импорта, массового заполнения, замены и исправления ошибок использует один снимок справочников и настроек проверок после чтения файла. Следующая операция читает настройки заново. Сохраняются проверка объединённой записи, номера версий и все одновременно обнаруженные ошибки.

Изменений схемы, новых миграций, лимитов, очередей или пользовательских настроек нет. Правила и интерфейс прежние, поэтому новая возможность в руководстве не описывалась.
