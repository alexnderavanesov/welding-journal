# История: изменения пользователя и системы — 02.11.2026

Реализовано локально. Старые события не переписываются; скриптов преобразования и действий на проде нет. Эта доработка не требует миграции БД. Изменения оставлены без коммита.

В новых операциях блок «Изменения пользователя» расположен первым, первая запись раскрыта. Автоматические последствия собраны в изначально свёрнутый блок. Например, результат и дата ВИК показаны сразу, итоговый статус, отметка ДНО и сформированное заключение — в автоматических изменениях. Автор у всей операции остаётся прежним.

Происхождение сохраняется сервером для каждого изменённого поля внутри существующей записи истории. Учитываются создание/правки/импорт стыков, НК и НК до ТО, первичные и повторные циклы ПСТО/ТВМТ, явные операции с документами и основные справочники/настройки. Ручное изменение даты документа или описания дефекта остаётся действием пользователя. Для WDI используется фактический режим расчёта, прочитанный сервером при сохранении.

Старые события и операции без определённого правила происхождения остаются нейтральными: система не угадывает автора отдельных полей. Значения до/после, общий автор, права просмотра и атомарность сохранения сохранены. Руководство пользователя обновлено.

## Скорость и память

- Дополнительных SQL/RPC, копий истории и фоновой обработки нет. Существующая запись истории получает небольшой признак происхождения поля.
- В сравнении на 1000 стыках, по три чередующихся сохранения каждого варианта: медиана **269 → 274 мс**, число SQL **12 → 12**, записей истории **1000 → 1000**. Это короткий локальный замер, не доказательство отсутствия любых задержек на проде.
- В этой двухполевой выборке размер сериализованного JSON увеличился примерно на **37 байт на запись** после первого прохода. Это размер JSON, не физическое место PostgreSQL. Дополнительное хранение ненулевое, но полные снимки повторно не сохраняются.
- Разделение обрабатывает только текущую страницу из 50 записей. Содержимое автоматического блока не монтируется до раскрытия; длинные значения остаются постраничными, закрытые страницы освобождаются из кеша. Поиск относится к текущей странице.
- Отдельно проверена классификация 200000 переданных строк в памяти; это не нагрузочный тест БД на 200000 стыков.

## Дополнение предкоммитной проверки

Исправлена классификация импортированных полей, которые сервер наследует из программы линии: исходные введённые значения теперь фиксируются до подготовки записи. История больше не принимает такие подстановки за ввод пользователя. Старые события не меняются; новых SQL или миграций нет. Реальный импорт, откат и изоляция параллельных операций перепроверены.
