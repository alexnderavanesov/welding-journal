# Возврат в журнал, ЛНК и ПСТО — 06.11.2026

**Исправлено локально по отдельному поручению пользователя.** После перехода в другой раздел и сохранения стыка из другого окна возвращение в журнал, ЛНК или ПСТО автоматически показывает актуальные строки. Ручное обновление больше не требуется. Фильтры, сортировка и группировка сохраняются; если стык перестал подходить под фильтр, показывается актуальный пустой результат.

Причина из [адресных замеров](targeted-performance-2026-11-06.md): повторное открытие с прежними фильтрами использовало идентификатор и версию старой таблицы. Общий источник трёх отчётов теперь различает посещения раздела: новая таблица начинает чтение без прежней версии, а поздние ответы и уведомления прежнего посещения не могут заменить её строки или объявить её готовой. Ограниченный повтор при конфликте первой загрузки относится к текущему посещению.

Пока пользователь остаётся в открытой таблице, чужое сохранение по-прежнему сопровождается «Есть обновления»; строки и выделение не заменяются самопроизвольно. Несохранённый черновик, проверка конфликта и самостоятельный снимок предпросмотра сохранены. Справка внутри приложения обновлена.

Проверено на текущей локальной сборке:

- Новые регрессии до исправления: 7 падений при 24 проходивших прежних проверках. После исправления — 70 успешных проверок источника данных, таблицы, сортировки, групп, уведомлений и предпросмотра.
- Chrome и WebKit: по 3 сценария возврата, каждый с обычными строками, группировкой и переходом к нулевому результату. Сохранение выполняется через реальную карточку во втором независимом браузерном контексте; ручного обновления и перезагрузки страницы в сценарии нет.
- В обоих браузерах также прошли сохранение открытой таблицы/выделения после чужой записи, открытие свежей карточки, конфликт с сохранением черновика и восстановление предпросмотра после ошибки.
- `pnpm typecheck`, `pnpm build`, проверка 186 ссылок RPC и `git diff --check` прошли. Проверки использовали только одноразовую локальную БД `127.0.0.1:5432/welding_tracker_e2e` и отдельное хранилище файлов; тестовые сервер и БД убраны.

Артефакты: `outputs/report-return-fix-2026-11-06/` (`before.log`, `unit.log`, `grid-unit.log`, `chrome-verified.log`, `chrome-preservation.log`, `webkit.log`). Первый браузерный проход в `chrome.log` выявил гонку самого сценария: повторные клики переключали сортировку ещё раз до завершения предыдущей загрузки. Проверка теперь выбирает точное направление через меню, сохраняя проверку порядка и указателя после возврата; отдельного изменения сортировки приложения не потребовалось.

Это исправление ошибки актуальности, а не обещание ускорения всех таблиц. Остальная оптимизация из [№ 3 списка тем](tasks-to-consider.md) не выбрана. Миграции не нужны. Изменения не закоммичены; production не менялся.
