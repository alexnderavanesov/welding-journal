Статус: реализовано и проверено локально 13.10.2026, включая согласованные четыре сценария ПСТО/перемещения. Без коммита, push и production-изменений. Предыдущие незакоммиченные изменения обязательных названий/дат сохранены.

## Требования

### Дополнение пользователя 13.10 — архив, запоминание и оформление

- Общая пара запоминается отдельно для ВИК, РК, ПВК, УЗК, ТВМТ и ПСТО после успешного создания заключений, в одной транзакции с результатами. Как разделение, это общая настройка журнала. Отмена, ошибка и индивидуальные поправки документов не заменяют запомненную пару; явно пустая общая пара запоминается. Массовые назначения в «Документах» эту настройку не меняют.
- При открытии окна пара подставляется без необходимости заходить во вкладку специалистов. Архивированные, отсутствующие и потерявшие нужный допуск специалисты не подставляются; остальные роли сохраняются. Поиск перенесён внутрь выпадающего списка, блоки растянуты на доступную ширину.
- В справочнике добавлены фильтры-счётчики «Все специалисты», «Действующие», «В архиве», подтверждаемое архивирование и восстановление. Архив исключён из новых назначений на клиенте и сервере, включая устаревшее открытое окно. Исторические ФИО/удостоверения и версии документов при архивировании не меняются.
- Карточка не меняет размер при переключении типа; столбец действий рассчитан на доступные кнопки (120 px для трёх); количество стыков выровнено по центру своего столбца и поля имени. Значок правила СП-07 получил тёмную подсказку при наведении и фокусе, ссылка сохранена.
- Миграция `0049_salty_king_bedlam.sql` сгенерирована из схемы Drizzle, проверена и применена на `main` только к `localhost:5432/welding_tracker`: флаг архива с default false и индекс. Рабочие записи сохранены; fixtures используются только в отдельной автоматически создаваемой пустой локальной БД.
- Проверка этой доработки: typecheck, production-сборка (142 RPC), 109 целевых модульных тестов в 16 файлах и итоговые 10 E2E на отдельной локальной БД прошли. Проверены сохранение/повторное открытие общей пары, отмена, исключение архива, архив/восстановление через UI без изменения документов, стабильные размеры карточки на 1600/390 px, поиск внутри списка, подсказка, ширина вкладки и выравнивание счётчика. Скриншоты карточки и вкладки просмотрены. В сборке остаётся прежнее предупреждение конфигурации `manualChunks/codeSplitting`, не ошибка сборки; конфигурация этой задачей не менялась.
- Автотестами ограничены запросы: один общий запрос выбора для 1000 документов, два пакетных чтения и одна запись назначения для 1/10000 документов, два чтения для загрузки запомненных пар. По коду пары ограничены шестью видами и 12 ID; счётчики справочника — один агрегат, только для реестра. Новый прогон на 200000 стыков и полный аудит не выполнялись: расширенные четыре сценария ПСТО остаются в согласованном будущем аудите. Коммитов, push, production-операций нет; локальный `/references` отвечает HTTP 200.

### Исходные договорённости

- Общий раздел «Клейма» переименовать в «Справочники», оставить вкладки «Клейма», «Технологические карты», «Параметры проверки», добавить «Специалисты».

- НК и ТВМТ: «Провёл контроль», «Выдал заключение» — только дефектоскописты соответствующего метода. ПСТО: «Оператор-термист», «Руководитель по ТО» — только термисты. Один человек допустим в обеих ролях, обе роли необязательны.
- При внесении новых результатов: вкладка «Специалисты» после «Заключения и имена», общая пара для создаваемых документов плюс индивидуальные поправки каждого документа, включая пустые значения. Индивидуальные поправки не затираются общими. Основные/до ТО/повторные НК, ТВМТ, ПСТО. Уточнение пользователя 12.10: дубль-контроль не менять, это документ заказчика.
- После создания назначения меняются только в «Документах»: две колонки и массовое действие; не в обычном редакторе документа/стыка. Уточнение оформления 13.10: нажатие на ячейку открывает отдельное окно с выбором, не разворачивает редактор внутри строки.
- Все старые документы и новые автоматически сформированные послойные заключения остаются без назначений. Послойным заключениям можно назначить специалистов через документы.
- Заявки, ЖСР, чек-листы и ЗНИ не затрагивать.
- Один пункт «Действия → Назначить специалистов», одно окно без режимов. У каждой роли: «Не изменять» (default), «× Очистить назначение», выбор ФИО. Выбор назначает/заменяет во ВСЕХ отмеченных документах. Очистка убирает ФИО и удостоверение только этой роли; карточка остаётся. До «Применить» изменений нет, итог назначений/замен/очисток виден в том же окне. Только отмеченные документы, без молчаливого частичного применения; проверка квалификации и конкурентных изменений. Разнородные НК/ПСТО не объединять в одну пару ролей (предложено выбирать однородную группу, отдельного подтверждения смешанного UX не было).
- Документ сохраняет snapshot ФИО/удостоверения при назначении. Правка карточки не изменяет документы. Явное переназначение, включая повторный выбор того же человека, берёт актуальные реквизиты. Журнала изменений/истории версий не делать. Другие реквизиты/состав/результаты не менять.
- Уточнение пользователя 12.10: объединение с разными назначениями не блокировать. Выбран разрешённый упрощённый вариант: предупреждение перед сохранением и пустые обе роли в итоговом документе. При одинаковых сохранённых ФИО/удостоверениях назначения сохраняются. Переименование и разделение сохраняют исходные snapshots, без обновления из карточек. Выбор новой пары прямо внутри объединения не включён в этот вариант.
- Дополнительное подтверждение пользователя 12.10: тот же порядок действует при объединении заключений вследствие контекстного переноса НК между этапами — при разных назначениях предупредить до сохранения и очистить обе роли только после подтверждения. Обычный перенос сохраняет ФИО и удостоверения.
- Согласовано и разрешено к реализации 13.10: единый подход в четырёх сценариях. Назначение/возобновление ПСТО и перемещение на назначенную линию предлагают основной НК → до ТО; отмена ПСТО и перемещение на неназначенную/отменённую линию предлагают НК до ТО → основной. По умолчанию сохранить этап; выбор отдельный для каждого стыка. Весь имеющийся комплект всех методов переносится вместе, включая заявки без результата; завершения всех методов не требуется. Целевой этап пустой, реквизиты полные, хронология/официальность проверены; заявка ПСТО, история ПСТО/ТВМТ и повторные циклы соответствующего стыка блокируют перенос, но не KEEP/отмену при их собственной допустимости. Пустое ошибочное назначение удаляется как прежде. Отдельной команды смены этапа нет. При операции с частью общего документа остальные стыки и их специалисты сохраняются. Сохранение атомарно; подтверждение очистки недействительно после изменения специалистов или состава объединяемых документов.
- Восемь отдельных семантических полей конструктора: ФИО и № удостоверения для каждой из четырёх ролей. В конкретном шаблоне видны только четыре применимых. Системные формы, preview, export берут snapshot документа; выгруженные файлы не меняются.
- Обновить встроенное руководство. Проверить UI, серверные правила, пустые/старые документы, шаблоны, очистку, отмену/повтор, конкуренцию и пакетную нагрузку без N+1.

## Ограничения проверки

Сохранность snapshots распространяется также на обычное исправление результатов/реквизитов (основные, до ТО и циклы ПСТО/ТВМТ): пересоздание записи документа не должно сбрасывать подписи. Неявное разделение наследует пару, объединение разных пар требует предупреждения/подтверждения с откатом всей правки до подтверждения; очистка относится только к итоговым конфликтующим документам. Это реализация общего согласованного правила сохранности назначений, не новый журнал истории.

Схема — Drizzle, миграции только генерировать и выполнять на main. Проверенная рабочая локальная БД может быть мигрирована с сохранением данных; fixtures/автотесты только в отдельно проверенной одноразовой локальной БД. Полный предкоммитный аудит и ранее отложенные планы не входят автоматически в эту задачу.
