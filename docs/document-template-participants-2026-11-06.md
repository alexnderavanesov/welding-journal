# Список участников работ в конструкторе — 06.11.2026

Реализован локально по прямому поручению пользователя. Новых полей справочников, таблиц базы и миграций нет. Изменения не закоммичены и не выпущены в production. Остальные идеи конструктора остаются в [списке кандидатов](tasks-to-consider.md).

## Как пользоваться

В общем или пользовательском шаблоне подготовьте шапку, одну пустую строку человека и подписи ниже. Удалите из бланка прежний заполненный список. В конструкторе назначьте данные ячейке этой строки, выберите «Создавать блок для → Каждого участника работ», отметьте категории и назначьте поля: № п/п, ФИО участника, специальность, № удостоверения, клеймо НАКС, внутреннее клеймо. Допустим и существующий многострочный блок на человека. Сводку по проекту или линии размещайте вне повторяемого блока.

Разряд/уровень, удостоверение сварщика, номер журнала, подписи и другие отсутствующие реквизиты пользователь заполняет вручную в скачанном Excel. Новые поля откладываются до отдельного решения. Инструкция добавлена в руководство приложения.

## Правила состава

- Состав относится только к выбранным стыкам документа. Сварщики определяются по шести официальным клеймам; фактические клейма не участвуют. Внутреннее клеймо и НАКС одной карточки дают одного человека. Архивные карточки учитываются, неизвестное клеймо остаётся с пустым ФИО.
- Исполнители берутся из сохранённых назначений связанных заключений НК, ПСТО, ТВМТ и послойного контроля: только «Провёл контроль» / «Оператор-термист». Заявки, проверяющие, начальники лаборатории и документы других стыков исключаются. Учитывается история, включая НК до ТО и повторные работы; ФИО и удостоверение берутся из заключения.
- Порядок: сварщики, термисты, дефектоскописты; внутри категории — по алфавиту. Однофамильцы разных карточек и разные сохранённые удостоверения не объединяются. Один исполнитель с разными историческими удостоверениями может занимать несколько строк.
- Каждый новый экспорт заново получает участников связанных стыков и заключений. История сформированного пользовательского документа при скачивании не переписывается. Ручные правки скачанного файла обратно в приложение не переносятся.
- Режим доступен общим и двум пользовательским видам документов. Системные заявки/заключения сохраняют свои специализированные правила. Доступ к источникам проверяется по выбранным категориям; нехватка прав не приводит к молчаливо неполному списку.

## Проверки

Пройдены проверка TypeScript, production-сборка и 109 профильных проверок: нормализация, конструктор, Excel, источники участников, права, границы шаблонов и сохранение правила текущего ПСТО/ТВМТ для обычных полей. Проверены пустой состав, фильтр категорий, нумерация, перенос подписей, сохранность исходного файла, разные удостоверения и однофамильцы.

В Chrome и WebKit на отдельной локальной базе `127.0.0.1:5432/welding_tracker_e2e` пройдены настройка/сохранение/повторное открытие конструктора, формирование и чтение Excel, исключение фактических клейм/подписантов/чужих стыков/заявок и новое скачивание после изменения исполнителя. Проверен также прежний сценарий двух пользовательских документов. Тестовая база изолирована от основной рабочей базы; production не использовался. Полный предкоммитный или системный аудит этим не заменяется.

## Последующие уточнения интерфейса и готовый пример

По просьбе пользователя подсветка повторяемого блока сделана светло-голубой, номер строки — мягким голубым, рамка текущей ячейки — тонкой. Списки полей расширены, поиск работает по названию и группе. После «Назначить данные» сразу появляется выбор поля; пустые назначения показываются с адресом ячейки и переходом к ней, вместо общего сообщения без адреса.

Первоначально по отдельному поручению настроен существующий `custom1` в основной **локальной** базе `localhost:5432/welding_tracker`: исходный файл «список сварщиков.xlsx» сохранён, `B2` выводит линию, `C3` повторяется для сварщиков и выводит ФИО с официальным клеймом в скобках. Режим — участники, категория — только сварщики. Название документа — «Список сварщиков — линия …». Изменена только конфигурация этого шаблона через серверный механизм с контролем версии; другие документы, записи и настройки не менялись. Резервная копия до изменения: `/tmp/local-welder-template-backup-20261106/`. Этот первоначальный вариант заменён формой по образцу ниже.

Подготовлен пример через действующий механизм Excel на существующей линии «2» проекта «Риформинг»: 10 стыков, 3 карточки сварщиков. Два одинаковых ФИО относятся к разным клеймам и не объединены. Файл: `outputs/welder-list-example-2026-11-06/Список сварщиков — линия 2.xlsx`. Настройка действует для выбранного состава любого документа, а не только для линии-примера. Для списка по одной линии выберите её в «Срез документа» или выделите все её стыки в журнале; период определяет, какие работы войдут в состав. После этой настройки уже открытый конструктор нужно закрыть и заново загрузить настройки.

Дополнительно пройдены 31 профильная проверка, TypeScript, сборка, прямой выбор поля из пустого назначения и полный экспорт в Chrome/WebKit на отдельной тестовой базе. Основная локальная база использовалась только для запрошенной настройки и чтения существующих данных примера, без тестовых записей. Управление Safari было недоступно: инструмент вернул отказ в разрешении. Настройка и её повторное чтение выполнены через локальный серверный код; проверки интерфейса — в изолированных браузерных сценариях.
