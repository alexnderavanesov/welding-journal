## Требования, которые нельзя потерять

- Авторизация уже реализована: Better Auth 1.7.14, приглашение 48 ч, восстановление 1 ч, сессия 24 ч, пароль от 6 символов; публичных регистрации/восстановления нет. Удаление аккаунта отзывает доступ, сохраняет историческое имя и рабочие факты; должность не права. [План](authentication-and-access-plan-2026-10-29.md), [матрица](authentication-operation-matrix-2026-10-29.md). Postbox HTTPS уже выбран, SMTP заново не внедрять. Для новой auth-задачи применять официальные MCP/skills с фактической версией lockfile.
- Соглашение только бумажное: [итоговый Word](legal/confidentiality-agreement-paper-2026-10-30.docx). Экран принятия/галочка/ЭДО/учёт подписания на сайте отменены; старые drafts и миграции не основание их возвращать.
- При прежнем невалидном официальном клейме разрешены несвязанные исправления при неизменных квалификационных входах, СП-02 остаётся. Системные поля меняются только профильными процессами; импорт/массовые операции проверяют итог после слияния и все одновременно обнаруживаемые ошибки. ЖСР/чек-лист/ЗНИ пользователя используют текущий цикл; системные документы — исторический. Цикл принадлежит стыку: разные номера разных стыков сами по себе не запрещают общий результат. Сохранять права, точные позиции/этапы/методы/даты, версии и атомарность.
- Помощь с потерянным ответом проверяет квитанцию, не повторяет запись вслепую; отсутствие квитанции не доказательство отката. Связи документов загружаются по требованию/порциями, полный состав не обрезается. Остальные требования — [линии](line-program-plan-2026-09-25.md), [системные правила](line-program-system-rules-plan-2026-09-30.md), [техкарты](technology-cards-plan-2026-10-08.md), [реквизиты документов](document-required-names-plan-2026-10-11.md).
- 200000 стыков — масштаб проверки, не новый лимит. Плановые 1,8–3 документа на стык означают 360000–600000 суммарно, не в каждом реестре. Полную историю/Excel/печать нельзя урезать под видом оптимизации.

## Ограничения нового чата

До нового явного поручения — только чтение и обсуждение. Не запускать реализацию, аудит, миграции, commit/push/deploy, production-команды, письма или инфраструктурные изменения. Старые разрешения исчерпаны выполненными задачами. Сохранить checkout/main, рабочие данные, процессы и незакоммиченную передачу; не делать reset/stash, не переключать ветку и не создавать worktree. Не архивировать старый чат, не отправлять ему команды, не запускать два runner на одной disposable БД.

Без субагентов по умолчанию: для новой задачи объяснить пользу и получить подтверждение; прежнее разрешение двум проверяющим относится к завершённому аудиту. Качество/полнота аудитов важнее экономии; модель и уровень выбирает пользователь, автоматически их не менять.

При отдельно разрешённой реализации **локальные миграции на main имеют постоянное разрешение**: проверить localhost/точное имя БД, сохранить данные, схема Drizzle → `pnpm db:generate` → просмотр → `pnpm db:migrate`. Не спрашивать повторно это разрешение и не писать SQL миграции вручную, но передача не запускает миграции. Remote — отдельное прямое разрешение и `pnpm db:remote-migration`. Fixtures/нагрузка/автотесты — только отдельная проверенная пустая локальная БД, изолированные файлы/auth/почта; рабочую БД не очищать и не засевать. При изменениях поведения обновлять `src/components/user-guide-page.tsx`.

В этой передаче сверены локальные Git, процессы, HTTP-ответ и документы. Новые тесты, нагрузка, миграции и production-действия не выполнялись; секреты не копировались.
